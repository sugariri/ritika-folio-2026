# The vault

`finsynth.html` and `locked.html` are AES-GCM ciphertext behind a password gate.
Both are generated output. The generator, the template, the extractor, the gate UI,
and the four limits worth knowing before sharing the page.

in it may name a block that now lives in a sibling file under `docs/`. `CLAUDE.md` itself

## Password-protected case page

`finsynth.html` and `locked.html` both hold a case study that cannot be published in the open. Ritika's brief was specific about what it must not be: *"Do NOT give me a simple JavaScript if/else password check, because that can be bypassed via View Source."* That constraint is what shapes everything below, and it is met **structurally rather than by hiding a comparison better**.

The page carries one **AES-GCM-256 ciphertext** and no password. AES-GCM is authenticated, so its 128-bit tag is verified as part of decryption: a key derived from the wrong password makes `crypto.subtle.decrypt()` reject. "Wrong password" is therefore a caught exception, not a branch a reader can find in the source and step over, and **patching the JS gets you nothing, because the plaintext is not in the file to be revealed.** The key comes from **PBKDF2-HMAC-SHA-256 at 600,000 iterations** (the OWASP floor) over a 16-byte random salt, with a 12-byte random IV.

**It is a generator plus a template, not a hand-written page, and that is forced by the one rule that matters here: the plaintext must never be committed.** A single hand-authored HTML file cannot satisfy that, because someone would have to paste the secret into it to encrypt it.

- `tools/encrypt-case.mjs` — the offline encryptor, run as `npm run lock`. It prompts for the password twice on a muted readline (or reads `CASE_PASSWORD` for CI), refuses anything under the length floor or obviously weak unless you pass `--allow-weak`, and substitutes **five** placeholders into the template: `__PAYLOAD__`, `__TITLE__`, `__HEADING__`, `__STANDFIRST__`, `__FOOTNOTE__` (`__HINT__` was the sixth until 2026-08-24). A missing placeholder is an error, not a silent pass — but note which direction that check runs in: the loop asserts that every key in `subs` appears in the template, so a **template** placeholder with no `subs` entry ships to the reader as literal text. Adding a slot to the template means adding it to `subs` in the same commit.
- `tools/locked.template.html` — the shell plus the gate, with the payload slot. **Since 2026-08-24 it also carries the agentation dev gate**, because the injected fragment cannot: `extract-case.mjs` lifts only `<style>` and `<main>`, and `innerHTML` runs no `<script>`. See `docs/dev-islands.md`.
- `tools/extract-case.mjs` — lifts the source page's `<style>` and `<main>` into a standalone injectable fragment (see **The content is a fragment of a real page** below). Its `--in` **defaults to `private/finsynth.source.html`, not `finsynth.html`** — that default was the live one until the published page became the vault, and leaving it would have had the extractor read its own output. Pointed at a vault page it fails on the first assertion rather than emitting a fragment, which is the intended failure.
- `private/` — where the plaintext lives, **gitignored**: `finsynth.source.html` (the hand-written page, the thing to edit) and `finsynth.plain.html` (the extracted fragment, build output). The encryptor's own last line says so: "Keep the plaintext out of git. Only `locked.html` is safe to publish." `.vercelignore` names `private/` for the same reason — a git-integration deploy never sees a gitignored directory, but a CLI `vercel deploy` from the repo root uploads the working tree, and that would put the plaintext on a public URL and undo the whole page.

What is in both pages today is the **FinSynth case study** (Ritika, 2026-08-23: "you put my finsynth case study in it"), behind the same six-character code. **One fragment, two vaults** — extract once, then run the encryptor once per output:

```bash
# 1. the hand-written source -> the injectable fragment
node tools/extract-case.mjs      # private/finsynth.source.html -> private/finsynth.plain.html

# 2. the fragment -> each published vault (same fragment, same code, same copy)
for out in finsynth.html locked.html; do
  npm run lock -- --in private/finsynth.plain.html --out "$out" --gzip --code \
    --title 'Vault · Ritika Shakkerwal' --heading 'Vault' \
    --standfirst 'This work is under NDA. Ask me for the key.' \
    --footnote 'this page keeps secrets. so do i. 😉'
done
```

The two pages are **not byte-identical and are not meant to be**: every build draws a fresh random salt and IV, so the same plaintext under the same password produces different ciphertext each time. Identical bytes would mean a reused IV, which is the one thing AES-GCM must never do. What has to match is the *content*, which is why they are built from one fragment in one pass rather than at two different times — a vault rebuilt alone goes stale the moment the source is edited, and that is exactly how `locked.html` came to be holding pre-edit content on 2026-08-24.

**The password is passed as `CASE_PASSWORD` for a scripted run** (`CASE_PASSWORD='…' npm run lock -- …`); with no env var the encryptor prompts twice on a muted readline, and it errors rather than hanging if stdin is not a TTY.

**`{n}` in `--footnote` becomes the number of boxes**, so a line that names the code's length cannot go stale when the code changes length — the copy is hers and the count is the build's. With no `--code` there is no count, and `{n}` is deliberately left alone rather than resolved into something untrue. **`--hint` is gone (2026-08-24)**, along with the line it filled: five placeholders now, not six, and the encryptor's assertion runs subs → template, so leaving the flag in a build command is an error rather than a stray line.

**The case study is behind its own URL now (2026-08-24).** Ritika: *"whenever i open this it never asks me vault password why"*, pointing at the deployed `finsynth.html`. The answer was that the vault and the case study were **two different files**: `locked.html` held an encrypted *copy*, while `finsynth.html` was still the open page — both publicly 200, her work card at `index.html:1751` pointing at the open one. So the vault was protecting a duplicate of something anyone could read. Given the choice she took **gate `finsynth.html` itself**, and kept the existing code rather than rotating it.

**The code itself is deliberately not written down here, or anywhere else in the repo.** It used to be, in this paragraph, until 2026-08-24 -- which made this file the one place a `git clone` handed over both the ciphertext and its key, and put it on GitHub the moment a branch was pushed. The hard rule in `CLAUDE.md` already said the password is passed as `CASE_PASSWORD` and never written to a file; a doc is a file. So the value lives with Ritika and nowhere in git, and the two records that disagreed about it (this paragraph said one thing, commit `7d9a9e8` "Reset vault password to 'legacy'" said another) are resolved by keeping neither: **check with her before a rebuild rather than trusting a string in a doc.** If a stale code was ever pushed, rotating is one rebuild.

So the file at `finsynth.html` is the vault build. Three consequences, and the first is the one that bites:

- **`finsynth.html` is generated output.** Hand-edit it and the next `npm run lock` silently reverts you — the same warning `locked.html` has always carried, now on the page every other section of this file describes. The case study source is `private/finsynth.source.html`, gitignored; **it is the file to edit**, and it is the only copy outside git history, so don't delete it. If it is ever lost, `git show <sha>:finsynth.html` from before 2026-08-24 has it.
- **The inbound link needed no change**, which is why this option was the recommended one: `index.html`'s work card still points at `finsynth.html`, and every link already shared still resolves. What changes is what the URL serves.
- **`locked.html` stays**, as the hand-off link — the same content behind the same code at a URL that is the case study and nothing else, for when she wants to show someone the work without handing them her portfolio's own route. Two identical vaults are not a security problem: the ciphertext is public in both, and the boundary is the password either way.

**One thing this does not close, and it is worth saying plainly:** the plaintext `finsynth.html` is still in the **public repo's git history**. Gating the live page does nothing about that — only a history rewrite or making the repo private does. That is hers to choose and has not been done.

**The gate is the Vault, not a password field (Ritika, 2026-08-23, from a reference image: "we can have this kind of UI for putting the password").** One rounded card centred on the page, holding a mono lowercase eyebrow (a 14px closed padlock plus the word `locked`), the `--h1` heading, a sans standfirst, **six one-character boxes and no submit button**, the failure line directly under them, and below a hairline the keep-unlocked checkbox. The `--footnote` sits **above the eyebrow** rather than under the hairline (2026-08-24, from an annotation on the gate: "move at the top and add a wink emoji") — so the card opens in her voice and the padlock answers it. Moving it out of `.gate-foot` meant the line had to state its own mono and `--faint` instead of inheriting them from that wrapper, which incidentally fixed the `<noscript>` copy: it has always been a sibling of `.gate-foot`, never a child, so it had never rendered as the mono line it was written as. The reference's own copy is what forced the box count: "6 characters. it opens itself." promised both the length and the auto-submit, so the gate has to keep both promises — the copy itself is gone (below) and the six boxes are what keep the first one now.

**Five changes on a single read-through of the card (Ritika, 2026-08-24), and four of them are deletions or moves rather than additions.** Read together they say the card was explaining itself: three separate lines described what the boxes were about to do, and the one line the reader needed on failure sat furthest from the boxes.

- **The eyebrow gets a padlock** ("add a loc icon"). It was a filled `.gate-dot`, on the argument written into the CSS that a padlock beside the word `locked` is the label drawn twice. She wants the glyph. It is `.gate-lock`, the same closed padlock `.nav-lock` draws at the same 1.9 stroke, 14px, `--muted` — nothing new was invented, and `aria-hidden` because the word beside it is the label.
- **The hint line goes** ("no need to write this.... this is odd"). Six boxes already say six characters and the auto-submit announces itself by firing, so `{n} characters. it opens itself.` was the UI narrated to someone already watching it. `.gate-help` and `__HINT__` went with it, and the slots' `aria-describedby` drops to `gateMsg` alone.
- **The AES-GCM / PBKDF2 footnote goes** ("do we need to show this?"). It is true, it is in this file, and there is nothing a reader can do with it at the gate. Her own closing line stays, because that one is voice rather than spec.
- **The failure line moves up to the boxes** ("when wrong, the text need to appear right next to the input area boxes"). It is now the last thing in the form, 14px under the row and flush with its left edge, where the eye already is when the row clears itself. It used to sit below the checkbox, a control away from what it was about.
- **The checkbox moves under the hairline** ("move the check box thing below the line"), which puts it outside `<form>`: `form="gateForm"` keeps it associated and the script only ever reads it by id. In `.gate-foot` it inherits mono `--faint`, so `.gate-keep` restates `var(--font)` and owns its own margins.

**The vault footer matches the case-study pages** (asked for in the same pass: "keep it similar to the case study pages"). It was her work address; `case.html` and `private/finsynth.source.html` both link `Ritikashofficial2511@gmail.com`, and the vault is a fourth copy of that block, so it says what they say.

Five things about it are load-bearing.

- **The payload records the box count.** `--code` writes `slots: <password length>` into the JSON, and the gate draws that many boxes; without it the field renders instead. So the boxes can never disagree with the real key — the alternative, a hardcoded six in the template, silently mis-asks the moment the code is rotated to a different length.
- **The two input modes are one abstraction.** `entry = slots ? buildCode(slots) : useField()` sits above both definitions (`var` and function-declaration hoisting is what allows that), each builder removes the other's markup so exactly one mode is ever live, and everything downstream — submit, error, clear, `sessionStorage` resume — talks to `entry` and never to an input. Adding a third way to ask means adding a third builder, not a branch at every call site.
- **The boxes are the OTP pattern, written out.** Typing advances, a paste spreads rightward across the remaining boxes, Backspace on an empty box steps back and clears, Arrow keys move, and the last character **auto-submits**. Enter is wired by hand, because with no submit button the form has no implicit submitter.
- **They stay at 16px mono**, the iOS zoom-on-focus guard the `.ask-input` rule already carries site-wide. 56×60 desktop, 44×54 at 390px.
- **A wrong code clears the row and returns focus to the first box** with `That does not decrypt this page. Check for a stray space, and mind the capitals.` in the `role="alert"` line, 14px under the boxes. It never says how many characters were wrong, because the only thing the page knows is that the tag failed.

**Six characters is a real trade, and the encryptor says so out loud every build.** The default floor is `MIN_PASSWORD = 12`; `--code` drops it to `MIN_CODE = 6` and refuses above `MAX_CODE = 24` (past that the boxes stop being a row). Against a public ciphertext a 6-character alphanumeric code is roughly 2.2e9 candidates, which is hours rather than years on one GPU at 600,000 iterations — right for a code you hand out and rotate, wrong for content that has to stay shut for years. That warning prints on every `--code` run rather than once in this file, because the page **publishes the length** by drawing one box per character, and the length is most of what sizes the job for an attacker. The six-box UI can hold a longer code at any time: it is one rebuild, and the boxes follow `slots`.

**The content is a fragment of a real page, and `tools/extract-case.mjs` is what makes it injectable.** Injection is `innerHTML`, so an inline `<style>` **applies** and a `<script>` **does not execute** — which means every JS-driven behaviour in the source page has to be replaced by its resting state, not merely left alone. The extractor performs each of those transforms behind an assertion, so a change to `private/finsynth.source.html` that breaks one fails the build instead of shipping a dead figure: the spotlight layer is cut, and ` reveal` is stripped so nothing is left faded out waiting for an `IntersectionObserver`. A third transform gave the anatomy figure's first region and first list item `class="on"`, so its cross-highlight was lit rather than blank; that figure was deleted from the source on 2026-08-24 and the transform is retired in place, its number kept so the ones after it keep their labels. **A retired transform is the good failure mode, not a tidy-up:** both of its `swap()`s went from one match to zero, and a `swap()` that matches nothing fails the build, so the source edit could not have quietly shipped a stale rewrite. It emits the Caveat and Inter `@import`s first, then the page CSS, then the static overrides. **The `.wf-nav` paging buttons stay `hidden`, on purpose** — they ship hidden and are only ever shown by measurement in JS, so hidden is their correct resting state; the rail still scrolls.

**Flattening is not the only option, and the Before/After switcher was the first thing to take the other one (2026-08-24).** The fragment runs no scripts; **the page it is injected into runs its own**. So a behaviour worth keeping can have its driver moved into `tools/locked.template.html` and armed after injection instead of being flattened away. The switcher was flattened for the usual reason — a tab pair with no driver is a dead control, so the extractor cut the `.evo-bar` and the `.evo-state-heading` and reinserted each `.evo-label` inside the figure it named, leaving both states stacked. Ritika, annotating the result on the unlocked page: *"why did this change?"* It reads as a redesign, because that is what it looks like; nobody but the source's editor can see that a switch used to be there. The driver is now `evoSwitcher()` in the template, called from `armContentDrivers()` at the end of `inject()`, ported from the source page unchanged — both states stay in the DOM and the switch only toggles `hidden`, so there is nothing in it for `prefers-reduced-motion` to disable, and arrow keys move between the tabs.

**The cost is that one interaction now lives in two files, and the fragment cannot tell that its driver is missing.** That is why the four rewrites did not simply disappear: their assertion half is still there as `keep()`, a third transform kind that changes nothing and only checks. The driver binds by class and id and returns silently on a miss, so without `keep()` a rename in `private/finsynth.source.html` would ship a dead switcher rather than failing the build — the precise failure every other transform exists to prevent. **Add a driver to the template, add its `keep()` to the extractor**, and note that `#evo-after` and `#evo-after-label` are now named in the stray-`hidden` allowlist beside `.wf-nav`: they are `hidden` because that is a tablist's start state, so that allowlist entry and that driver are one decision in two places. Delete the driver and those two go back to being genuine strays, which the build will then say out loud.

**Two more took that route the same day, and one of them had never been cut on purpose at all (2026-08-24).** Ritika, reading the unlocked page: *"so many things i can notice got deleted, restore that. my page index is missing, my navigation dov for the analyst, the old product, the limitation etc is gone.."* Those are two different failures wearing the same face. The **story-tab band** was a deliberate cut, on the argument recorded above it that nothing hides behind the band so the four chapters read as one sequence without it. That argument was about the *content* and it held; what it missed is that the band is also the reader's **map of the opening**, and its four labels are the only place the words *The analyst*, *The problem*, *The old product* and *The limitation* appear as a set. Losing the map is a loss even when no chapter is lost, so the band keeps its markup and its driver moves to `storyTabs()` in the template. The panels keep `role="tabpanel"` and their `aria-labelledby`, because a tablist whose panels are not panels is worse than no tablist.

**The section rail was the other one, and it was never a decision.** `<nav class="index" id="caseIndex">` is a **sibling** of `<main>`, not a child, and the extractor sliced `<main>`…`</main>`. So the rail was dropped by the shape of the slice, and dropped **silently** — the one omission in a file where every other one is asserted, which is exactly why it survived several builds and had to be found by a reader rather than by the build. It is sliced explicitly now, asserted for `id="caseIndex"` and for its 11 links, and its driver is `sectionIndex()`. That driver's first act is to **move the rail out of `main`**, which is not tidying: the rail sits at `z-index: 50` and the band at `55`, and `main` is `position: relative; z-index: 1`, so a rail nested inside `main` is trapped in `main`'s stacking context and the band paints over it. Being a sibling is load-bearing (see `docs/case-shell.md` on the 168px rail top), and the injection has to put back the relationship the source page relies on. The `asksection` listener is deliberately **not** ported: a vault ships no chat, so there is nothing to emit it.

**The lesson generalises past these two: a silent omission is worse than a loud one, and "outside `<main>`" is where they hide.** Anything the source page keeps as a sibling of `<main>` — the rail today, the ask-me pill and drawer already — leaves the fragment without a word from the build. When a behaviour goes missing from an unlocked page, check the slice before checking the transforms.

**A vault carries the ask-me chat's CSS and no chat, and that is a real content loss (found 2026-08-24).** The extractor lifts `<style>` and `<main>`, and the pill and the drawer are direct children of `<body>` — so the fragment ships `--ask-pill-bg`, `.ask-pill`, `.ask-pill-send`, `.ask-pill-label`, the `body.chat-open` and attract hooks and the ≤560px override, with no markup to dress and no `QA` array at all. `tools/locked.template.html` supplies none either. It is not a bug in the extractor: `<script>` cannot execute under `innerHTML`, so carrying the driver would ship a dead pill, which is worse than shipping none.

What it costs is specific and worth knowing before the next cut. **The cut-copy rule assumes a reader can ask** — a line comes off the page and becomes a `QA` entry precisely so the argument stays reachable — and behind the gate nothing is reachable, so every cut-copy answer on this page currently lives only in `private/finsynth.source.html`. That makes each such cut a straight deletion from the published page's point of view. Two ways out, both Ritika's: leave the entries where they are against a future un-gated build, or carry the pill, the drawer and the driver into the template, which means the template growing a real `<script>` and the extractor emitting the `QA` data for it. Until one of those happens, a cut that matters should be weighed as a deletion rather than as a move.

Two things about the assets. The fragment keeps the source page's own **relative** `assets/finsynth/...` paths, so **both vaults have to sit at the repo root** for the images to resolve, and every asset the sealed fragment names has to be **committed** — a vault that opens onto broken images is the failure mode here, and the ciphertext gives no hint which file is missing. And they keep `loading="lazy"`, which is worth knowing before writing a checker: an image below the fold reports `complete === false` and reads as broken to a naive count. Force `loading = 'eager'` and scroll the page before believing any such number.

**Four limits, all of them worth knowing before this page is shared.** The **ciphertext is public** — it ships in the committed file, so it can be taken offline and ground with no rate limit and no way to revoke it; password strength times KDF cost is the entire security boundary, which is why the encryptor's length gate is a hard stop rather than a warning. `crypto.subtle` needs a **secure context**, so the page decrypts over https or from localhost and nowhere else; it detects that and says so rather than crashing. Injection is `innerHTML`, per the paragraph above. And the page is `noindex, nofollow, noarchive, nosnippet` with `referrer: no-referrer`, and its `<title>` stays generic until unlock so nothing leaks to a crawler or a tab. **That last one is a real cost now that `finsynth.html` is a vault**: the case study's own URL is `noindex` and titled `Vault`, so the portfolio's strongest page is invisible to search and shows no name in a shared link preview. It is the correct behaviour for content under NDA and it is the trade the gating decision bought; it is worth knowing before wondering where the page went.

**Two deliberate non-features**, both rejected as security theater rather than overlooked: no attempt counter and no artificial delay on failure. The 600,000 PBKDF2 iterations are the real cost centre, and a counter in client-side JS is a line the attacker deletes. The one convenience that is there is a **"Keep this tab unlocked while I read" checkbox**, under the hairline since 2026-08-24,, which stores the password in `sessionStorage` under `lockedCase.pw` and nowhere else; unticked, a reload returns the gate. A stored password that no longer decrypts is cleared silently rather than reported as the reader's mistake.

**The way back out is a padlock in the header, and it has to be there rather than in the gate (2026-08-23).** The checkbox is a one-way door on its own: it stores the password, every later reload self-unlocks, and the checkbox that set it is **gone** by then, because injection is `main.innerHTML = html` and the gate lives inside `main`. So a `change` listener on `#gateKeep` that clears the stored value is inert in the only case that matters, and the fix is a control that survives the injection. `<header id="siteHeader">` is a **sibling of `main`**, so `.nav-lock` sits in `.nav-right` beside the theme switch: click it and it clears `sessionStorage.lockedCase.pw` and reloads, which finds no stored value and draws the gate. Forgetting the password *is* the whole action.

Four things about it. It ships **`hidden`** in the markup and is unhidden by `inject()`, so it only exists once there is something to lock, which is the same ship-hidden-show-by-code contract `.wf-nav` and `.shelf-nav` follow. **`.nav-lock[hidden] { display: none }` is load-bearing** — `display: inline-flex` outranks the UA's `[hidden]` rule, the exact gotcha written into `.wf-nav[hidden]` on `finsynth.html`. Its geometry **restates `.nav-back`'s** 36px circle rather than joining that rule, because the `.riri-logo` → `.nav-back` → `.nav-right` CSS region is byte-identical to `case.html` and stays that way; nothing new was drawn, it is the circle the site already owns. And the glyph is a **closed** padlock, showing the destination state rather than the current one, which is the convention the theme switch's `title` already uses. Icon-only, so it carries both `aria-label` and `title` ("Lock this tab again") — the footer-marks rule.

Verified in headless Chrome against the served page: gate on first load with the lock hidden, unlock with the keep box ticked leaves the content injected and the lock visible with `lockedCase.pw` stored, a reload self-unlocks, a click clears the key and returns the gate with the lock hidden and the title back to `Vault · Ritika Shakkerwal`, and a wrong code still fails on the tag alone. Geometry 36×36 with the same 14px gap to the switch at 1440 and 390 in both themes, `docScrollX: 0`.

**Optional gzip, and the payload describes itself.** `--gzip` compresses before encrypting (`node:zlib` at level 9 in, `DecompressionStream('gzip')` out) and records `compress: 'gzip'` in the JSON, so the gate never has to be told which way the page was built. It earns its place on this content: 189.9 kB of plaintext becomes 50.8 kB of ciphertext and a 108.6 kB page. The payload travels as `<script type="application/json">` with base64 fields, which is safe in a `<script>` block for a mechanical reason worth keeping: base64's alphabet contains no `<`, so nothing in it can close the tag.

**Shell parity is an obligation here, not a nicety.** `locked.html` and `finsynth.html` carry copies of the header the case shells own, and the following blocks are **byte-identical to `case.html`** and verified as such: the `.theme-switch` CSS (all five pages, MD5 `0d4a184f…`), the riri wordmark SVG markup, and the whole `.riri-logo` → `.nav-back` → `.nav-right` CSS region. It also carries the pre-paint `<head>` theme script, the theme driver IIFE and the header-hairline IIFE verbatim. **Change the shell and this is a fourth and fifth file to change** — and the change goes in `tools/locked.template.html`, then **both** pages are regenerated. Editing either built page by hand puts it out of step with the template and the next rebuild silently reverts you.

Its token block is **trimmed to what the page actually uses** and carries the two per-theme switch aliases (`--switch-track` / `--switch-knob`) that every page needs; the rest of the site's tokens are deliberately absent. The gate itself is drawn in the site's own material — hairline, one radius, tokens only — and the injected content brings the case-study grammar with it in its own `<style>`, so copy written like a `CASES` entry (masthead, `.chapter-num`, `.chapter-gloss`, `.chapter-key`, centred `figcaption`, `.beat`, `.close`) renders correctly with no page edit.
