# Ask-me chat

The floating pill, the drawer, the chips and composer, the follow-up pills, the
first-visit attract, resize and pop-out, and the cut-copy rule that feeds the `QA` array.

Split out of `CLAUDE.md` on 2026-08-24; the text is unchanged, so a **bold cross-reference**
in it may name a block that now lives in a sibling file under `docs/`. `CLAUDE.md` itself
keeps the commands, the file map, the type scale and the hard rules.

**Ask-me chat:** A floating input-shaped bar (`.ask-pill`, bottom-**right** corner at `right: 24px; bottom: 24px` — see **The pill's corner and its cat** below, 400px wide with avatar left and a `.ask-pill-send` arrow circle right — a button styled as a chat input, not a real field) always labeled "Ask me about the case study" — the label never rotates or changes (deliberate; suggested questions appear only as chips inside the drawer); clicking it slides in a right-side drawer (`.ask-drawer`) while the page squeezes left (≥1100px: right padding = `--ask-w`, and the squeezed content steps its scale down via `zoom: var(--ask-zoom)` on `main`/`footer`; `zoom`, not `transform: scale`, because it re-lays-out and leaves no dead scroll space; pane mode only, popped-out chat leaves the page at full scale. `--ask-zoom` is computed in `applyPane()` — `clamp(0.5, (innerWidth − paneW − 32) / 660, 0.85)` — so widening the drawer shrinks the 660px column live until it fits the space that's left). The pill has to win against the column it floats over, so it is a card, not a hairline: its ground is `--ask-pill-bg` (true white / `#22222b`) a clear step off `--bg` rather than `--bg-float`, its resting border is `--line-hover`, its label is `--text` at `--t-body-md`, and `--shadow-pill` (pill-only) is deep enough to read as floating. `:focus-visible` draws a `--glow-ink` ring so the browser's default blue one never appears. **Scripted, not generated** — the drawer says so in `.ask-note`, and that honesty is the point; never wire it to a live model without asking. **Two pages have one — `case.html` and `finsynth.html`; `index.html` has none** (its chat only ever existed inside the case overlay, and went with it). Q&A entries are `{ q, k: [keywords], f: [follow-up questions], a: [paragraphs] }`: in `case.html` they live per-case in `CASES[key].qa`, concatenated with `GLOBAL_QA` (contact/about) at render — a case with no `qa` gets no pill at all. The first entries double as suggestion chips (up to 3 unasked, right-aligned inside the `.ask-composer` above the input — see **The chips and the input are one composer** below). Typed questions are keyword-matched in `matchQA` (keyword hit = 2 pts, question-token hit = 1, threshold ≥ 2); misses get `ASK_FALLBACK`, which admits the limits and points to the footer contact. Answers stream word-by-word after typing dots; a `.ask-sr` live region announces the finished answer; `prefers-reduced-motion` renders instantly. Both copies are page-level: the pill/drawer are direct children of `<body>` and `body.chat-open` drives the squeeze. `finsynth.html`'s differs only in its data and rail handling (single `QA` array with `SEED_COUNT` rotating seeds, `body.chat-open` drives the squeeze and fades out the section rail `.index`, which would otherwise collide below ~1440px — but moving the cursor to the rail's home corner (top-left) peeks it back in: a mousemove hotspot toggles `body.rail-peek` with a larger leave- than enter-threshold so it doesn't flicker, and the peeked rail sits on a flat `--bg` halo so it stays legible over the squeezed column) — keep the two implementations in sync if the interaction changes. FinSynth answers claim only facts verified in `case-study-inputs/FINSYNTH-INTAKE.md` (pilot, no invented numbers, honest authorship split) — keep them that way.

**The label names the page, and it was "Search anything about me" (2026-08-23, Ritika, annotating `.ask-pill-label`: "Ask me about the case study").** Her words are the label. The old copy was a search box's promise on a control that is not a search box and does not reach the whole site: what it answers is *this* case study, so the label now says which conversation it opens. Four things about it. It changes in **both chat pages** per the keep-the-two-in-sync rule, and it is true in both — `case.html` renders a case study too. It is still the **fixed** label the rule above describes; naming the page is not the same as rotating a question into it. The span is the pill's **accessible name** (the button carries no `aria-label`), so this is a screen-reader change as much as a visual one. And the width holds: 27 characters render at **295px** in a 400px pill (261px in the 366px pill at 390), so `.ask-pill-label`'s `text-overflow: ellipsis` never fires — verified in both themes at 1698 / 1440 / 390. `index.html` has no pill, so there is no third copy.

**Cut copy becomes a question (`finsynth.html`, 2026-08-23):** Ritika, annotating the pill: *"whatever text we are now eleminating can be somehow kept in the history so that we can use it in to be part of … this this div's questionare."* The page has been getting shorter all day — 01 lost its gloss and its four why-not-ChatGPT paragraphs, 02 lost its gloss and "The loop is the tidy version.", 04 lost its gloss, its same-contract paragraph and its pull, the masthead roster collapsed two engineer lines into one — and every one of those cuts was made for length, not because the argument was wrong. So the argument is kept where a reader can still ask for it: **a line that comes off the page becomes a `QA` entry, not a deletion.** Five went in under a `/* ——— Cut copy lives on here ——— */` comment that says so. **That comment is gone and the count is stale** — the array is grouped by three headers now and holds 25 entries; see **Three corrections to this file's account of the `QA` array** under the system diagram. The rule below is what survived, and it is the rule that matters.

Five rules govern the block, and the first two are what make it honest. The paragraphs are **page copy re-punctuated, never reworded** — the no-em-dash sweep's own rule (a dash is a joint, not a word) applied to text that is being moved rather than edited, so each answer is still claiming exactly what the page claimed. And they are still bound by the evidence rule: the headcount entry (`Three engineers: two on the backend, one on the frontend`) traces to the `[VERIFIED 22 Aug 2026]` team shape in `case-study-inputs/FINSYNTH-INTAKE.md`, which is also why it can say in the chat what the roster deliberately doesn't say in the grid — same split as the authorship answer.

The other three are mechanical. Each entry is **section-tagged (`s:`)**, so the argument resurfaces as a chip in the chapter it was cut from — the ChatGPT answer in 01 and 02, the old-workflows answer in 03 and 04, the headcount in 07. The block sits **immediately after the fifth entry, not at the end of `QA`**: `chipPool()` ranks tagged entries in array order and `renderChips` takes `slice(0, 3)`, so appending them left them ranked behind the older tagged entries and dropped from `job` and `problems` — the exact two chapters they were cut from — while inserting them above `SEED_COUNT`'s five leaves the seed chips untouched. And **keyword ties resolve to the first-listed entry** (`score > bestScore`), which is a real collision here: "how many engineers" scored 2–2 against *How did you work with engineering?* until `engineers` was added to the headcount keywords (4 vs 2, with "how did you work with engineering" still landing on the collaboration entry at 3 vs 2). Multi-word keywords are dead weight in `matchQA` — `keys.indexOf(t)` compares against single tokens — so keep `k:` entries to one word each.

**The pill's corner and its cat (`finsynth.html` only, 2026-08-23):** Ritika, annotating the pill: *"this just not pop out, maybe me shift it to right corner.. and on top of this, add the existing cat we build for folio, just sitting on top of this div, and waving at you in intervals, and also making sure the tail keeps waving it need to be 1.5x of current height."*

**The corner is her own fix for the not-popping-out.** Centred on `left: 50%`, the pill floated on the **reading column's own axis** — the same 660px centre line every paragraph, figure and caption is aligned to — so a floating control read as one more centred element in the stack. In the corner it is off the column entirely, and it is the corner the drawer opens from, so the pill and the panel it summons share an edge. Only the anchoring changed; the card, the ground, the border, `--shadow-pill` and the label are all untouched. The ≤560px override needed `right: 12px` alongside its `width: calc(100vw - 24px)` — right-anchored, the old rule would have run the pill 12px past the left edge.

**It is 400px wide, and it was 520 (Ritika, 2026-08-23: "reduce the width").** 520 was width the label was not using: it sat in 415px of box for 188px of type. At 400 the label keeps ~107px of slack, so it still never ellipses and the box still reads as an input rather than as a shrink-wrapped button, which is the one thing its width has to say. Nothing else in the pill moved — the attract ring pings on an expanding `box-shadow` rather than `scale` precisely so a non-square pill can't stretch into an oval, so it is width-agnostic — and below the ≤560px override the pill is full-width regardless. **Both chat pages carry the same number**, per the keep-the-two-in-sync rule, even though only `finsynth.html`'s pill is in the corner: `case.html`'s is still centred on `left: 50%`.

**The cat is `index.html`'s sitting cat, copied and made ornamental.** The grid, the `PAL` map, `pxRects()` and `pxSvg()` are lifted **verbatim** from index's script, including the tail group's `pxRects(…, 25, 23)` offset — which is why `.ask-cat .cat-tail-sit` can carry the same `transform-origin: 50px 54px` index uses. **That copy is a sync point**: retouch the sitting grid on `index.html` and this one drifts. What is deliberately *not* borrowed is the behaviour — no cursor tracking, no chase/flee/caught states, no paw prints. `finsynth.html` now has a cat and still has neither of the other two whimsies; the pill's cat is a fixture on a button, not the character that lives on the portfolio.

**"1.5x of current height" was read as the cat, not the pill** — the three clauses before it are all about the cat, and the pill's own problem was answered by the corner move she proposed in the same sentence. So `.ask-cat` is **96px**, 1.5× the 64px box index's `.hide-seek-cat` uses (72px on phones). If she meant the pill, that is 52px → 78px and a separate change.

Four things about how it is drawn. It is `position: absolute` inside the pill at `bottom: calc(100% - 11px)`, so it sits **on** the pill's top edge with its art overlapping by a few pixels rather than hovering above it — sitting on the div, which is what she asked for. It is **artwork, so it never flips with the theme**, same rule as index's cat and the sticky notes. It is `pointer-events: none`, `user-select: none` and `aria-hidden` — the pill is a button with an accessible name, and a decorative cat must not eat a click on it or add words to it. And it fades out with the pill under `body.chat-open`, because it is part of the pill, not a separate layer.

**The wave is intervals, the tail is continuous** (her sentence asks for both, and they are two animations). `askCatWave` is a 6s cycle that holds the paw raised for ~3.5s and then waves three times, because a paw waving without pause reads as a metronome and the tail is already the unbroken motion; `askCatTail` sways every 2s, and `askCatBreathe` gives the whole sprite a 2px rise. The raised arm is a **new mini-grid**, appended after the body the way the tail is, and two things place it: its base overlaps the body outline by two cells so rotating about that base can never open a gap at the shoulder, and it starts below row 17 so it is under the whiskers rather than waving through them. It is on the cat's **left**, the flank the tail is not on — both are small outlined cream shapes, and on the same side the eye read them as two tails. Rotation is **negative** (SVG turns clockwise, and on the left flank a positive turn swings into the face). Under `prefers-reduced-motion` all three animations stop and the paw **stays raised** — that is a pose, not motion.

**Ask-me first-visit attract:** A reader can still look straight past a quiet pill, so 1.4s after landing it gets one three-beat nudge in site purple: `.ask-pill.attract` breathes its border via `::before` (`ask-breathe`, `--glow-strong` + a `--glow-soft` bloom), pings one expanding ring via `::after` (`ask-ping`, a spreading `box-shadow` — not `scale`, which would stretch a 520×50 ring into an oval), and flips `.ask-pill-send` to `--glow-ink` (`ask-send-glow`). Both pseudo-elements are absolutely positioned, so they are not flex items of the pill, and the pill's own border stays the resting hairline underneath. The driver (`askAttract()`, next to the pill's click handler in both files) shows it **once per session** (`sessionStorage.askPillNudged`, so finsynth → case navigation doesn't re-nudge) and **never to someone who has already used the chat** (the shared `localStorage.askIntroSeen`); hover, focus, or opening the drawer cancels it early, and a 7s timer clears the class. Under `prefers-reduced-motion` the CSS drops the animations and holds the border lit instead — the hint survives, the pulsing doesn't — and that same timer is what puts it away. `index.html` has no pill, so it has none of this.

**Ask-me resize & pop-out:** The drawer's left edge is a drag handle (`.ask-resize`, keyboard: arrow keys on the focused separator) — width lives in `--ask-w` on `:root` so the page squeeze tracks it 1:1 (`body.ask-dragging` kills transitions mid-drag; JS clamps width to 300–720px, leaving ≥380px of column in squeeze mode). A header button (`.ask-head-pop`) toggles Zoom-style pop-out: `.ask-drawer.pop` + `body.chat-popped` turn it into a floating rounded window positioned by `--ask-x`/`--ask-y`, dragged by its header, right-edge-pinned when resized, clamped fully on-screen; the squeeze and rail-hide apply only to pane mode (`.chat-open:not(.chat-popped)`). Geometry persists in `localStorage.askPane`, shared by both chat pages. Below 700px the handle and pop button are hidden and a popped window auto-docks on resize; below 560px the drawer is full-width. `case.html` and `finsynth.html` each carry a copy of this — keep them in sync.

**Ask-me intro & section-aware chips:** Opening the drawer on an empty log runs `askIntro()`: a short `ASK_INTRO` orientation message — streamed word-by-word the very first time (`localStorage.askIntroSeen`, shared across both chat pages), rendered instantly on later opens so the log never starts empty; chips render after it. On `finsynth.html` only, the suggestion chips follow the reader: the section-rail tracker broadcasts the active chapter (`window.__askSection` + an `asksection` CustomEvent on `document`), QA entries carry `s: [section-ids]` tags, and `chipPool()` puts entries tagged with the current section first, padded with seeds. The `asksection` listener re-renders chips only when the drawer is open and not mid-answer (`ask.busy`), and `renderChips(keepScroll)` skips identical re-renders (`lastChips` key) and skips `scrollLog()` for section-triggered updates so page scrolling never yanks the chat log. `case.html` has the intro but not section chips (its tick rail tracks chapters for its own `aria-current` and broadcasts nothing); its chips are just `c.qa` in order.

**The chips and the input are one composer (2026-08-23, Ritika, annotating `#askChips`: "this is part of input div. also correspond to the adjasent section.").** Two complaints in one line, and they are two separate defects.

**The grouping half:** the hairline sat on `.ask-form`, so the chips band floated above a bordered input and read as a third region of the drawer rather than as suggestions belonging to the thing you type into. The border moved up onto a new **`.ask-composer`** wrapper that holds both, so one box is bounded and the chips are inside it: `.ask-chips` repadded `0 16px 12px` → `12px 16px 4px` (the 12px is now above the chips, 4px between the last chip and the input), and `.ask-chips:empty { display: none }` collapses the band entirely — without it the composer carried a stray 12px of padding while the first-visit intro was still streaming and there was nothing to suggest yet. Nothing was drawn: same chip, same ground, same hairline, one level of nesting.

**The correspondence half was a real bug, and the cause was the squeeze.** Her screenshot proved it: standing in `#fia` she was shown `job`-tagged chips. Opening the drawer applies `zoom: var(--ask-zoom)` to `main`/`footer`, the document gets ~15% shorter, and under an unchanged `scrollY` the reader lands two chapters away (measured `fia` → `system`); the rail's `aria-current` moves with them and the chips faithfully answer for a chapter nobody is looking at. So **`askKeepPlace(mutate)`** wraps both the `chat-open` add and remove: it measures the current section's `getBoundingClientRect().top` before the class change and again after, and corrects `scrollY` by the difference. Three things about it:

- **The anchor is the section the reader is in**, `window.__askSection` on `finsynth.html` and the `.case-rail a[aria-current='true']` target on `case.html` — the same fact each page already tracks, so no new state.
- **`behavior: 'instant'`, not `'auto'`.** `'auto'` defers to the page's own `scroll-behavior`, which is smooth, so the correction animated: measured `#fia` at 213 → -950 at 60ms → 167 at ~760ms, a visible 1,000px glide back. With `'instant'` the anchor holds still (measured 106 → 106 at 1698, 582 → 581 across the close) and the fix lands in the same frame the layout changed in.
- **It preserves the reader's place, not the rail's label.** On `case.html`'s close the anchor holds to the pixel while `aria-current` re-resolves from `#ch-3` to `#ch-2`, because an un-zoomed page puts a different chapter boundary across the tracker's 42% line. That is cosmetic there (its chips are not section-keyed); on `finsynth.html`, where the chips do depend on it, the section is `fia` before, during and after in every tested width and theme.

**Follow-up pills (2026-08-23, Ritika, annotating `#askLog`: "but based on the questions asked one the answer is given there also some follow up question pill is needed to continue the chat with resp to the prev question asked").** After an answer, up to two pills appear **inside that answer's own `.ask-msg-body`** ("there") offering where it leads. `renderFollow(entry, msgBody)` runs from the stream's completion callback, which is why `streamAnswer`'s `done` now takes the body element it wrote into.

- **Each entry names its own follow-ups, in a `f: [question strings]` list**, resolved against `QA` by question text. Explicit over inferred: a keyword-overlap or shared-`s:`-tag heuristic would have produced *related* questions, which is not the same as a next step, and it would drift silently every time a keyword list is retuned. Resolving by text rather than by index also means the data reads as prose and a renamed question fails loudly (no pill) instead of pointing at the wrong answer.
- **They are disjoint from the composer's chips.** `ask.follow` holds the current picks and `renderChips` filters them out alongside `ask.asked`, so the reader never sees one question offered in two places at once (verified `overlap: []`).
- **Left-aligned, and that is what distinguishes them.** `.ask-follow` is `align-items: flex-start` with `.ask-follow .ask-chip { text-align: left }` against the composer's right-aligned column: same object, and its side of the drawer says whether it belongs to an answer or to the input.
- **Already-asked entries are skipped**, so a chain dries up rather than looping, and the terminal question carries no `f:` at all: *How do I get in touch?* on `finsynth.html` (14 of the 15 entries there at the time), and on `case.html` the follow-ups stay inside the three case questions rather than reaching into `GLOBAL_QA`, which is the "never shown as chips" rule that block already carried.

Both changes are in **`finsynth.html` and `case.html`**, per the keep-the-two-in-sync rule. Verified in both themes at 1698 and 390: `composerBorder: "1px"` / `formBorder: "0px"`, the empty band collapsed while the intro streams, follow-ups in the message body with no chip overlap, a second answer raising its own set, `docScrollX: 0`, no page errors, and `node --check` clean on every inline script in both files.
