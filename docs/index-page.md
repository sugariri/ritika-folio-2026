# `index.html`

The portfolio page: the cat and paw prints, the loading animation, the card shelves,
the Experience chronology, Community, Beyond work, the hero-as-About, the footer,
the Toolkit, and the section order.

Split out of `CLAUDE.md` on 2026-08-24; the text is unchanged, so a **bold cross-reference**
in it may name a block that now lives in a sibling file under `docs/`. `CLAUDE.md` itself
keeps the commands, the file map, the type scale and the hard rules.

**Interactive cat:** A `position: fixed` SVG cat element tracks the cursor. It's a kawaii pixel-art "sprout kitty" — each of its four states (`sitting` front-facing, `chasing` side-profile stalk, `fleeing` stretched run, `caught` happy closed-eyes purr) is a 32×32 character grid passed to `pxSvg()`, rendered as 2px `<rect>`s in a 64×64 viewBox with `shape-rendering: crispEdges`; colors live in the `PAL` map. Animated parts (sitting tail, hearts, fleeing legs) are mini-grids rendered via `pxRects(rows, ox, oy)` inside classed `<g>` groups appended after the main grid — if you move them, update the matching `transform-origin` in the CSS (`.cat-tail-sit`, `.cat-legs-flee`). State changes swap `innerHTML` entirely. The cat chases when the user is scrolling, flees when the mouse moves fast within 250px, and sits otherwise. If the cursor lands on it (or it's tapped/clicked), it's `caught`: it purrs with a doodle speech bubble (`.cat-bubble`, a separate fixed div that tracks the cat) saying “Purrrr”, then wriggles free after 3s with 1.5s of catch immunity. This is the one intentional bit of whimsy — keep it intact across redesigns.

**Paw prints:** A pooled set of 24 `div.paw` elements (plus 4 cat emoji elements) are recycled via index cycling. They spawn on click and on hover over interactive elements (throttled to 2.5s), suppressed while scrolling. The hover selector lists the interactive classes — update it if row/link class names change.

**Loading animation:** `index.html` only — first paint is one pixel field across the **whole first screen** in **two inks**: the hero spotlight photo rises out of bricks in the side margins (outside the dashed column guides) while the content column is bricked in the page's **own ground tone**, a faint pixel shimmer with no photo behind the copy. Same grid, same landing beats, so it reads as one field rather than two effects. Two earlier versions were tried and rejected: margins-only left a flat strip down the middle that read as a hole in the effect, and running the photo wall-to-wall put a sunset behind the copy. The point of the two-ink split is that the *content* pixelates too — the copy is pixel-erased for about a second and comes back crisp when the field fades. Pixels first, deliberately (Ritika chose this over keeping the copy legible throughout). Adapted from the Animation Curator "Pixel Assemble" effect, with four deliberate departures: it **keeps the photo's colour** (the source drained it to grey, which is right for a b&w Wall St plate and wrong for a sunset), it **never resolves to the sharp photo** (the mosaic is the whole reveal — the sharp version is what the spotlight lens is for), it **plays once** instead of looping, and it is **brisk** — ~950ms to settle plus a 420ms fade, because an intro the reader is looking past should be over in about a second, not announced. `.loader` is a body-level `position: absolute` full-width div (z-index 10000, above the cat band at 9997) holding one canvas, with **no background of its own** — `draw()` starts with `clearRect`, not a ground fill, so the bricks assemble *over* the live page instead of on a curtain: the page is never hidden, only overdrawn, and because the element keeps `pointer-events: none` throughout with no scroll lock, every link is clickable from the first frame. **Absolute** rather than fixed so it scrolls away with the page if the reader moves before it finishes, and **body-level** rather than inside `.hero` so it can also cover the sticky header, which is opaque and which a child of `main` (`z-index: 1`) could never rise above. Its height is one `window.innerHeight` — the first screen, which is all the reader can see at load. The driver is the second IIFE in the script. One grid: `cols = round(vw / TILE)` (8px bricks), `cell = vw / cols`, rows filling the screen bottom-aligned. Which ink a cell gets is decided by its **centre** against `guides()`, which recomputes `body::before`/`::after`'s expression off the same `--content`/`--gutter` tokens, so the changeover lands exactly on the dashed guide; margin cells are sampled from one photo laid out `cover` across the full width (the middle is sampled too and simply never used, which is what makes the two bands read as one image behind the page), and column cells get `groundTone()` — the resolved `body` background jittered by `±JITTER` (9) per channel on a second, decorrelated `sin` hash (`seed2`, so the tonal noise doesn't stripe along the same lines as the landing order), signed by `LIFT` so bricks lift off a dark ground and sink into a light one instead of clamping flat at 0/255. Bricks land bottom-to-top on deterministic scattered beats (a `sin` hash, never `Math.random`, so the order is identical on every load), each dropping in from just above its slot and popping home with an ease-out-back overshoot, with a 0.75px bleed so sub-pixel cell widths leave no seams. `REVEAL_WINDOW` (0.22) is wider than the source's 0.16 because the short timeline would otherwise flick each brick into place too fast to read as a landing — shorten `ASSEMBLE_MS` further and it needs widening again. `MIN_BAND` (72px) suppresses **only the photo**, not the loader: below it the margins are slivers where a sunset would read as noise, so narrow windows and phones get the ground-tone field alone. Because that field needs no network, a slow or broken photo costs nothing — `IMG_CAP_MS` and `onerror` both call `start()` ground-only rather than dismissing (an empty rectangle was the old failure mode), and a photo that arrives after `started` is ignored so the ink never swaps mid-assembly. Once the last brick settles the mosaic **is** the wait state: it holds until `window.load`, capped at `WAIT_CAP_MS`, then fades out and the element **removes itself from the DOM** — nothing of it survives the load, and it adds nothing to layout while it lives (page `scrollHeight` is identical with and without it). Killed in CSS *and* JS under `prefers-reduced-motion`, same as the spotlight, so a reduced-motion reader never sees a frame. `finsynth.html` and `case.html` have none — a loader on every case-study navigation would be a tax, not a flourish.

**Work cards:** Two **shelves**, stacked, each a horizontal card rail under its own `.sec-label`: `#work` (four cards: **FinSynth AI — Product** → `finsynth.html`, **FinSynth AI — Landing page** → <https://finsynth.ai/> in a new tab, **Mazic** → the Framer case study in a new tab, **Event Beep** → `case.html?c=eventbeep`) and `#side` ("Side projects" — vibe-coded projects like Animation Curator, plain external links). `#work` carries the nav anchor and a tighter `padding-bottom: 44px`, so the two read as one browse layer sitting above the Experience chronology.

These were **one section behind an ARIA tab toggle** (`.work-tabs` / `#panel-work` / `#panel-side`) and that was replaced on purpose (Ritika, 2026-08-21): a tab hid half the work behind a click and forced two lists of very unequal length to share one control. Both groups are now visible at once. Don't reintroduce the tabs.

Each shelf is `.shelf` (`position: relative`, `--shelf-card: 272px`) → `.shelf-rail` (the scroll track) + two `.shelf-nav` buttons. The rail **bleeds out to the dashed column guides** — `margin: 0 calc(var(--gutter) * -1)` with matching `padding` — so cards start flush with the 572px column and the next one is cut at the guide rather than at the text edge: the cut *is* the affordance that says there is more. Cards are `flex: 0 0 var(--shelf-card)` with `scroll-snap-align: start` under `scroll-snap-type: x proximity`, and the rail **must** carry `scroll-padding-inline: var(--gutter)` — without it the snapport is the border box, snap rests the rail at `scrollLeft: 24`, and the first card lands on the guide instead of the column with the back button lit over nothing. Native scrollbar hidden (`scrollbar-width: none` + the `::-webkit-scrollbar` reset); swipe, trackpad and drag all still work.

`.shelf-nav` is a 36px circle on `--bg-hover` with `--shadow-row`, pinned just inside the guide (`left`/`right: calc(var(--gutter) * -1 + 6px)`) and sitting on the **plate's** vertical centre (`top: calc(var(--shelf-card) * 9 / 16 / 2)`, not the card's — the two-line foot would drag it low), so it overlaps the cut card. Both buttons ship `hidden` in the markup and are only ever *shown* by measurement in the shelf IIFE, which pages by one card + gap (measured off two real cards, so retuning `--shelf-card` or the gap needs no JS change) and re-syncs on scroll, resize, `ResizeObserver`, and each lazy shot's `load`. So a shelf that fits its column (Side projects, one card) shows no buttons, and with the script dead the rails still scroll — the buttons are an accelerator, never the only way through. Below 640px `--shelf-card` becomes `min(272px, 78vw)` and the buttons go entirely: swipe is the affordance on touch, and a button with no hover to explain it would just sit on the cards.

The card itself is the site's only card, and it is kept inside the design direction: hairline `--line` border, 14px radius, **no** shadow at rest. Structure is `.card` → `.card-art` (16/9 plate) + `.card-foot` (`.card-title` with a right-aligned `.card-arrow`, then a one-line `.card-sub`). Hover mirrors `.row` exactly — fills to `--bg-hover`, border to `--line-strong`, `--shadow-row` — and `.card-arrow` uses `.row-arrow`'s width/opacity/translate transition on the same `.35s cubic-bezier(.22,.61,.36,1)`, so the grid and the rows below read as one family. One column below 640px (arrow hidden — there is no hover on touch, and the whole card is the target).

The plate comes in two kinds. **Where the project is live, the plate is a snapshot of the real thing** (Ritika, 2026-08-21) — `.card-art.shot` pads 8.5% and lays three soft radial tints over a ground (`--plate-<name>-a/-b/-c/-ground`) with one `img.card-shot` inset on it (`object-fit: cover`, `object-position: top center`, 8px radius, `--shadow-shot`, `scale(1.02)` on card hover). This is the one place photography earns its way in: it is the work, not decoration. All four `#work` cards use it, classed `.plate-product`, `.plate-landing`, `.plate-mazic`, `.plate-beep` — each tint set is pulled from the site it frames, and like the rest of the artwork these tokens **never flip with the theme** (a light screenshot inset on a dark plate reads as a glitch), which is why `--shadow-shot` is one set for both themes rather than a `--shadow-*` pair. **Everything without a live site keeps the type mark**: `.card-mark` sets the project name as a lowercase slug with the slash in `--faint` (`<i>/</i>animation-curator`), because those have no mark to show and a stock glyph would be decoration standing in for content. `#side` is all type marks today.

The shot plate needs `display: grid; min-height: 0` and `min-height: 0` on `.card-shot` to actually *be* 16/9: a box with `aspect-ratio` still takes a content-based automatic minimum, so each screenshot's own ratio (553 vs 562 tall at 1000 wide) was overriding the plate and leaving heights — and therefore titles — 2px apart across the rail. Zeroing that minimum lets the ratio win; the grid parent is what gives `height: 100%` a definite box to resolve against. All five cards now measure identically (216 tall, 152 plate). Cards keep their width on the rail at every breakpoint, so the plates keep 16/9 on phones too — the old `.card-art:not(.shot)` flatten to 5/2 and the 6.5% shot padding existed only because a card used to go full-width at one column, and both are gone.

Screenshots live in `assets/cards/` as ~1000px-wide JPEGs, `loading="lazy"` with intrinsic `width`/`height` so the grid never reflows: `finsynth-product.jpg` is cropped from the in-repo `assets/finsynth/hero-agent.png`; `finsynth-landing.jpg`, `mazic.jpg` and `eventbeep.jpg` are headless captures of the live sites at 1440×810 (16:9, so nothing is cropped). Two captures need care — Mazic's "Made in Framer" badge is hidden with a style tag before the shot, and Event Beep needs a scroll-down-and-back nudge or its creator videos shoot as black rectangles. To refresh one, re-capture at 16:9 and re-emit at the same width so the plate padding lands identically.

**Beyond work (`index.html`):** `#life` — six captioned polaroid prints (Travel, Reading, **Cats**, Music, Food, Fitness) on a third `.shelf`, from the second reference of the same day: six overlapping tilted prints fanned across the full page width.

**Six prints do not fan across a 572px column, so the fan became a rail.** `.life-shelf` is the same `.shelf` the Work and Side cards ride — bleeding to the dashed guides, snapping, paging by the same measured step, swiping on touch, buttons gone below 640px — and the reference's overlap doubles as the shelf's own affordance: a print half behind the next one says there is more, exactly the way a cut card does. So nothing here is a new interaction, only a new item shape on an existing rail.

The frame flips with the theme and the picture inside it does not — a print is page furniture, a photograph is artwork, which is the split the token block already draws; a rack of white rectangles on near-black would be the brightest thing on the page. The well inside the frame needed its own token, **`--print-well`** (`#ececee` / `#141419`), because the only thing it has to be is **darker than the frame around it**, and in dark theme `--bg-secondary` is *lighter* than `--bg-hover` — which turned the print inside out. `.give-shot` keeps `--bg-secondary` on purpose: a recessed tile sitting on the page ground reads either lighter or darker.

Two alternating tilts (`nth-child(odd)` −2.4°, `even` +1.8° with a 12px drop) rather than a random angle per print — a fan, not a spill — and later siblings paint over earlier ones, which is what gives the stack its left-to-right lean with no z-index bookkeeping. Hover straightens and lifts a print (`--shadow-pill`, `z-index: 3`) and inks its caption, the same muted-at-rest / ink-under-the-cursor move `.card-mark` makes. The rail carries `padding-block: 22px 26px` so the tilt and the lift live *inside* the scroller: `overflow-x: auto` forces `overflow-y` to compute to `auto`, so anything exceeding the box conjures a phantom vertical scrollbar (measured: the rail's `scrollHeight - clientHeight` is 0). Reduced motion drops the travel and keeps the tilt, which is a layout rather than motion. `.polaroid` is also in the paw-print hover selector — update it there if the class is renamed.

**Three shelf changes came with it, all verified non-regressive.** `.shelf-rail > .card` became `.shelf-rail > *` and the driver's `rail.querySelectorAll('.card')` became `rail.children`, so a rail sizes and pages any direct child (measured after: `#work`'s step is still exactly 288px = 272 + 16). `.shelf-nav`'s vertical position became `top: var(--shelf-nav-top, calc(var(--shelf-card) * 9 / 16 / 2))` — the plate's centre by default, with `#life` handing in `44%` because its items are not 16/9 plates. And `.shelf-nav` gained `z-index: 4`, above a lifted print's 3; the card shelves have nothing competing there, so it changes only that one case.

**Optional photos:** both new sections ship their `<img>` slots already pointed at `assets/community/mentoring-1…4.jpg` and `assets/life/{travel,reading,cats,music,food,fitness}.jpg`, and **none of those files exist yet** — the sections render as labelled `.shot-empty` plates until they do. An IIFE just above the shelf driver removes any `img[data-optional]` that fails to load, plus any that is already `complete` with `naturalWidth === 0` (a cached failure can land before the listener and fire no event), so a missing file falls back to the plate rather than a broken-image icon. Adding a photo is therefore a file copy, not an edit; it runs *before* the shelf driver so a rail measures itself after any missing print has already gone. The six captions are the reference's own placeholders except **Cats**, which is the one this site had already earned — swap them for whatever is true, the fan holds any count.
