# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Development

No build step — this is a static site of three self-contained pages. Serve locally with:

```bash
python3 -m http.server 8766
```

Then open `http://localhost:8766/`.

## Architecture

Three pages, each with its HTML, CSS, and JS inline — no framework, bundler, or runtime dependency; the only external request is the Inter webfont from Google Fonts (`finsynth.html` also loads Caveat for the problem wall).

- `index.html` — the portfolio itself: hero, work rows, about, education, toolkit, contact. Home of the interactive cat and paw prints.
- `finsynth.html` — the long-form FinSynth case study, with its own section rail, figures, and ask-me chat.
- `case.html` — one template that renders any of the five short case studies from `?c=<key>` (`scream`, `mazic`, `yomo`, `slyce`, `eventbeep`), in finsynth's shell.

`finsynth.html` is the reference implementation of the shared shell (nav, masthead, chapters, close, reveal, theme, ask-me chat) and `case.html` carries a copy of it — when the shell changes, change both.

**Design direction:** Deliberately minimal, in the spirit of salleedesign.com — single 660px column, left-aligned, hairline rules between rows, near-monochrome palette, type doing all the work. No shadows, gradients, or decorative graphics. Keep it that way: new sections should be a `.rows` list or a `.pairs` definition list, not a new visual pattern. The **one** exception is `#work`'s `.cards` grid (below) — added deliberately because the work itself deserved tiles; everything else stays rows.

**Animation:** No animation library. Sections tagged `.reveal` fade up once via an `IntersectionObserver`. Everything else is CSS transitions. `prefers-reduced-motion` disables the reveal and smooth scrolling.

**Interactive cat:** A `position: fixed` SVG cat element tracks the cursor. It's a kawaii pixel-art "sprout kitty" — each of its four states (`sitting` front-facing, `chasing` side-profile stalk, `fleeing` stretched run, `caught` happy closed-eyes purr) is a 32×32 character grid passed to `pxSvg()`, rendered as 2px `<rect>`s in a 64×64 viewBox with `shape-rendering: crispEdges`; colors live in the `PAL` map. Animated parts (sitting tail, hearts, fleeing legs) are mini-grids rendered via `pxRects(rows, ox, oy)` inside classed `<g>` groups appended after the main grid — if you move them, update the matching `transform-origin` in the CSS (`.cat-tail-sit`, `.cat-legs-flee`). State changes swap `innerHTML` entirely. The cat chases when the user is scrolling, flees when the mouse moves fast within 250px, and sits otherwise. If the cursor lands on it (or it's tapped/clicked), it's `caught`: it purrs with a doodle speech bubble (`.cat-bubble`, a separate fixed div that tracks the cat) saying “Purrrr”, then wriggles free after 3s with 1.5s of catch immunity. This is the one intentional bit of whimsy — keep it intact across redesigns.

**Paw prints:** A pooled set of 24 `div.paw` elements (plus 4 cat emoji elements) are recycled via index cycling. They spawn on click and on hover over interactive elements (throttled to 2.5s), suppressed while scrolling. The hover selector lists the interactive classes — update it if row/link class names change.

**CSS custom properties** (in `:root`): colors and the font stack. Every color is a variable — that is what makes the dark theme below a single token block instead of a second stylesheet. Never hardcode a color in a rule; add a token.

**Light / dark theme:** All three pages ship both themes. A tiny inline `<head>` script (before `<style>`, so there is no flash of the wrong theme) resolves `localStorage.theme` — else `matchMedia('(prefers-color-scheme: dark)')` — into `data-theme="light|dark"` on `<html>`. Because of that, each file needs exactly **one** `:root[data-theme="dark"]` block right after `:root` (no duplicated `@media (prefers-color-scheme)` palette, and no `light-dark()` — its invalid-at-computed-value fallback is a trap). The driver JS is the first IIFE of the main `<script>`: it wires the header `.theme-toggle` (sun glyph in light, moon in dark; the label names the theme you'd *get*), updates `meta[name=theme-color]`, and follows the OS *only* while no explicit choice is stored. `localStorage.theme` is shared, so a choice made on any page holds on all of them — keep the head script, the driver, and the toggle markup identical in the three files.

Tokens split three ways, and the split is the whole design:
- **Page furniture flips** — `--bg`, `--bg-card`/`--bg-raised`/`--bg-stage` (finsynth) / `--bg-secondary` (index), `--text`/`--muted`/`--faint`, `--line*`, `--brand`/`--logo` (both lift to `#a97bff` on near-black, where `#752afc` vibrates), `--fail`, `--ok`, `--ask-pill-bg` and the `--glow-*` set (the ask pill's surface and its attract ring), and the `--dia-*` diagram ink (drawn figures are only ink on the page's own ground, so they invert with it).
- **Artwork never flips** — the pixel cat, the pale `--note-*` sticky notes and the `--gray-*` ramp they're written in, the blush `--chrome-*` browser frame, the `--art-bg/-ink/-muted/-line` set behind it, `--blue-core` (the mat, the favicon, the "better way" note), the traffic lights, the mat shadows. A light product screenshot must not end up framed in half-dark chrome, and a negative of a face or a sticky note reads as a glitch. `--blue-ink` exists purely so diagram blue can flip while `--blue-core` stays put; `.paw-cat` exists so the paw prints can invert while the emoji cats only brighten.
- **Shadows are per-theme** (`--shadow-row/-pill/-panel/-drawer/-pop/-note`): a soft black blur does nothing on a dark page, so the dark set is deeper and tighter. Surfaces that need to lift off near-black use `--bg-float` instead of a shadow (the ask drawer/pill/chips) — `--bg` there left them indistinguishable from the page behind.

Colors deliberately do **not** transition — a color transition would collide with `body { transition: padding-right }` during the chat squeeze.

**Row hover:** `.row` replicates salleedesign.com's work-row interaction — the row fills into a white pill, `.row-role` slides open (`max-width` 0 → 100%), `.row-end` opens its `column-gap` 0 → 12px, and `.row-arrow` eases in (`width` 0 → 16px, `translateX(14px)` → 0), all on `.35s cubic-bezier(.22,.61,.36,1)`. Below 640px there is no hover: the role is always visible and the arrow/divider are hidden. `.row-static` rows (Education) never light up and always show their role.

**Section rail:** `finsynth.html` only (`.index`, fixed in the left margin, pinned at `top: 112px` — top-aligned, not vertically centred — and positioned off `--content`/`--gutter` so it sits outside the column; hidden below 1120px where the margin can't hold it) — `case.html`'s chapters have no rail. No header and no numbers: one `<a>` per chapter hanging off a **continuous hairline rail** (`ol { border-left: 1px solid var(--line) }`), with the active chapter's segment inked in — `a::before` is a 1px bar at `left: -1px` spanning the row, `--text`, `scaleY(0)` → `scaleY(1)` for `aria-current='true'` on `.28s cubic-bezier(.22,.61,.36,1)`. It is `scaleY` from a top origin rather than an animated `height` so a chapter change stays on the compositor and can never reflow the rail. Inactive labels are `--muted` (not `--faint` — an inactive item still has to be readable) and go `--text` on hover. `li.sub` (the three decisions inside 07) steps only the *label* in; the inked segment stays on the one shared rail line. An earlier version replaced the rail with a per-chapter horizontal tick under a `Table of Contents` header — reverted on purpose; don't bring it back. `aria-current` is set by the scroll tracker (the same one that broadcasts `asksection` to the chat), so the rail and the suggestion chips always agree on which chapter you are in.

**Spotlight reveal:** A hidden photo revealed through a soft-edged lens that trails the cursor. **Exactly two places have one** — `index.html`'s hero and `finsynth.html`'s masthead. The five short case studies deliberately have none: `case.html` contains no `.spotlight` markup, CSS, or driver at all, because a photo behind that column fought the copy. Don't add one back. Each `.spotlight` layer (absolute, `inset: 0`, `pointer-events: none`, `overflow: hidden`) holds a fixed-size `.spotlight-lens` (760px, radial-gradient `mask-image`, moves via `style.translate`) containing a `.spotlight-img` sized to the host from JS and counter-translated each frame so the photo appears pinned while the lens roams. The image lives in `:root` as `--spotlight-hero-img` (`assets/spotlight-hero.jpg`) — a real photo, chosen to hold color edge-to-edge. The driver IIFE (end of the script) arms `layer.parentElement`: snap + fade in on `mouseenter`, lerp (0.09) on `mousemove`, fade out on `mouseleave`; the rAF loop stops when settled. Disabled by both CSS and JS under `prefers-reduced-motion`, `hover: none`, or ≤640px. Keep it below z-index 60 (header) and never at/above 9997 (cat band); hero copy sits above it via `.hero .wrap { z-index: 1 }`. `finsynth.html` carries its own copy of the same CSS + driver on its masthead (`.masthead-band` hosts the layer; image in `--spotlight-img`, a b&w Wall St photo at `assets/finsynth/spotlight-wall-st.jpg` (any spotlight image must hold tone edge-to-edge — one that fades to white reads as an empty lens)) — keep the two implementations in sync if the interaction changes.

**Loading animation:** `index.html` only — first paint is one pixel field across the **whole first screen** in **two inks**: the hero spotlight photo rises out of bricks in the side margins (outside the dashed column guides) while the content column is bricked in the page's **own ground tone**, a faint pixel shimmer with no photo behind the copy. Same grid, same landing beats, so it reads as one field rather than two effects. Two earlier versions were tried and rejected: margins-only left a flat strip down the middle that read as a hole in the effect, and running the photo wall-to-wall put a sunset behind the copy. The point of the two-ink split is that the *content* pixelates too — the copy is pixel-erased for about a second and comes back crisp when the field fades. Pixels first, deliberately (Ritika chose this over keeping the copy legible throughout). Adapted from the Animation Curator "Pixel Assemble" effect, with four deliberate departures: it **keeps the photo's colour** (the source drained it to grey, which is right for a b&w Wall St plate and wrong for a sunset), it **never resolves to the sharp photo** (the mosaic is the whole reveal — the sharp version is what the spotlight lens is for), it **plays once** instead of looping, and it is **brisk** — ~950ms to settle plus a 420ms fade, because an intro the reader is looking past should be over in about a second, not announced. `.loader` is a body-level `position: absolute` full-width div (z-index 10000, above the cat band at 9997) holding one canvas, with **no background of its own** — `draw()` starts with `clearRect`, not a ground fill, so the bricks assemble *over* the live page instead of on a curtain: the page is never hidden, only overdrawn, and because the element keeps `pointer-events: none` throughout with no scroll lock, every link is clickable from the first frame. **Absolute** rather than fixed so it scrolls away with the page if the reader moves before it finishes, and **body-level** rather than inside `.hero` so it can also cover the sticky header, which is opaque and which a child of `main` (`z-index: 1`) could never rise above. Its height is one `window.innerHeight` — the first screen, which is all the reader can see at load. The driver is the second IIFE in the script. One grid: `cols = round(vw / TILE)` (8px bricks), `cell = vw / cols`, rows filling the screen bottom-aligned. Which ink a cell gets is decided by its **centre** against `guides()`, which recomputes `body::before`/`::after`'s expression off the same `--content`/`--gutter` tokens, so the changeover lands exactly on the dashed guide; margin cells are sampled from one photo laid out `cover` across the full width (the middle is sampled too and simply never used, which is what makes the two bands read as one image behind the page), and column cells get `groundTone()` — the resolved `body` background jittered by `±JITTER` (9) per channel on a second, decorrelated `sin` hash (`seed2`, so the tonal noise doesn't stripe along the same lines as the landing order), signed by `LIFT` so bricks lift off a dark ground and sink into a light one instead of clamping flat at 0/255. Bricks land bottom-to-top on deterministic scattered beats (a `sin` hash, never `Math.random`, so the order is identical on every load), each dropping in from just above its slot and popping home with an ease-out-back overshoot, with a 0.75px bleed so sub-pixel cell widths leave no seams. `REVEAL_WINDOW` (0.22) is wider than the source's 0.16 because the short timeline would otherwise flick each brick into place too fast to read as a landing — shorten `ASSEMBLE_MS` further and it needs widening again. `MIN_BAND` (72px) suppresses **only the photo**, not the loader: below it the margins are slivers where a sunset would read as noise, so narrow windows and phones get the ground-tone field alone. Because that field needs no network, a slow or broken photo costs nothing — `IMG_CAP_MS` and `onerror` both call `start()` ground-only rather than dismissing (an empty rectangle was the old failure mode), and a photo that arrives after `started` is ignored so the ink never swaps mid-assembly. Once the last brick settles the mosaic **is** the wait state: it holds until `window.load`, capped at `WAIT_CAP_MS`, then fades out and the element **removes itself from the DOM** — nothing of it survives the load, and it adds nothing to layout while it lives (page `scrollHeight` is identical with and without it). Killed in CSS *and* JS under `prefers-reduced-motion`, same as the spotlight, so a reduced-motion reader never sees a frame. `finsynth.html` and `case.html` have none — a loader on every case-study navigation would be a tax, not a flourish.

**Case studies:** Real pages, **never modals** — they used to open as an overlay on `index.html` and that was removed on purpose (Ritika: "no pop ups"). Work cards in `#panel-work` point wherever the work actually lives — `case.html?c=<key>` for Event Beep, `finsynth.html` for the FinSynth product, and straight out to the live site for FinSynth's landing page and for Mazic (see **Work cards** below); the `#experience` rows are the ones that still link every case; `case.html` reads the key from `?c=` (falling back to `#key` / `#case-key`), looks it up in the `CASES` object in its inline script, and renders masthead → numbered `.chapter` per `sections[]` → optional `.case-cta`, in `finsynth.html`'s shell. An unknown or missing key renders a visible "Case not found" page rather than redirecting, so a broken href is debuggable. To add a project: add a `CASES` entry in `case.html`, add its key to `CASE_ORDER`, and add an `#experience` row — and add a `.card` to `#panel-work` **only if there is work to show**, since a card is a promise of something to look at (see **Work cards**). The copy in `CASES` is a first draft — it is not verbatim from Ritika — **except `mazic`**, which was rewritten from Ritika's own published case study at <https://ritikamazicv1.framer.website/> and claims only what that page claims (2-month build, team of five, pivot off an interactive-demo tool, 100 beta users day one, 200+ active users, $1,009 gross in Dec 2024, Magic Balls AI award). Treat those numbers as sourced and don't invent neighbours for them; the same rule as the FinSynth intake applies.

The Next chain is the header, not the body: `.nav-back` is a static "← Back" → `index.html#work`, and `#caseNext` is filled from `CASE_ORDER` (`['scream','yomo','slyce','eventbeep']`)  and stays `hidden` on the last case. **Mazic is not in the chain**: its card and its `#experience` row link straight out to <https://ritikamazicv1.framer.website/> in a new tab, because Ritika's own Framer case study is the canonical one. `CASES.mazic` is kept so `case.html?c=mazic` still resolves for any link already in the wild, but nothing on the site points at it. `finsynth.html` carries the same header statically, with Next pointing at `case.html?c=scream`, so the whole chain reads finsynth → scream → yomo → slyce → eventbeep. The chain is **no longer a mirror of the card grid** — scream, yomo and slyce have case pages but no card (there is no work to show in a tile yet), and they are reached from the `#experience` rows instead, so the chain has to be maintained on its own. The old `index.html#case-<key>` addresses still work: a short shim near the top of index's script forwards them to `case.html?c=<key>`.

**Ask-me chat:** A floating input-shaped bar (`.ask-pill`, bottom-center, `left: 50%` + `translate`, 520px wide with avatar left and a `.ask-pill-send` arrow circle right — a button styled as a chat input, not a real field) always labeled "Search anything about me" — the label never rotates or changes (deliberate; suggested questions appear only as chips inside the drawer); clicking it slides in a right-side drawer (`.ask-drawer`) while the page squeezes left (≥1100px: right padding = `--ask-w`, and the squeezed content steps its scale down via `zoom: var(--ask-zoom)` on `main`/`footer`; `zoom`, not `transform: scale`, because it re-lays-out and leaves no dead scroll space; pane mode only, popped-out chat leaves the page at full scale. `--ask-zoom` is computed in `applyPane()` — `clamp(0.5, (innerWidth − paneW − 32) / 660, 0.85)` — so widening the drawer shrinks the 660px column live until it fits the space that's left). The pill has to win against the column it floats over, so it is a card, not a hairline: its ground is `--ask-pill-bg` (true white / `#22222b`) a clear step off `--bg` rather than `--bg-float`, its resting border is `--line-hover`, its label is `--text` at `--t-body-md`, and `--shadow-pill` (pill-only) is deep enough to read as floating. `:focus-visible` draws a `--glow-ink` ring so the browser's default blue one never appears. **Scripted, not generated** — the drawer says so in `.ask-note`, and that honesty is the point; never wire it to a live model without asking. **Two pages have one — `case.html` and `finsynth.html`; `index.html` has none** (its chat only ever existed inside the case overlay, and went with it). Q&A entries are `{ q, k: [keywords], a: [paragraphs] }`: in `case.html` they live per-case in `CASES[key].qa`, concatenated with `GLOBAL_QA` (contact/about) at render — a case with no `qa` gets no pill at all. The first entries double as suggestion chips (up to 3 unasked, right-aligned above the input). Typed questions are keyword-matched in `matchQA` (keyword hit = 2 pts, question-token hit = 1, threshold ≥ 2); misses get `ASK_FALLBACK`, which admits the limits and points to the footer contact. Answers stream word-by-word after typing dots; a `.ask-sr` live region announces the finished answer; `prefers-reduced-motion` renders instantly. Both copies are page-level: the pill/drawer are direct children of `<body>` and `body.chat-open` drives the squeeze. `finsynth.html`'s differs only in its data and rail handling (single `QA` array with `SEED_COUNT` rotating seeds, `body.chat-open` drives the squeeze and fades out the section rail `.index`, which would otherwise collide below ~1440px — but moving the cursor to the rail's home corner (top-left) peeks it back in: a mousemove hotspot toggles `body.rail-peek` with a larger leave- than enter-threshold so it doesn't flicker, and the peeked rail sits on a flat `--bg` halo so it stays legible over the squeezed column) — keep the two implementations in sync if the interaction changes. FinSynth answers claim only facts verified in `case-study-inputs/FINSYNTH-INTAKE.md` (pilot, no invented numbers, honest authorship split) — keep them that way.

**Ask-me first-visit attract:** A reader can still look straight past a quiet pill, so 1.4s after landing it gets one three-beat nudge in site purple: `.ask-pill.attract` breathes its border via `::before` (`ask-breathe`, `--glow-strong` + a `--glow-soft` bloom), pings one expanding ring via `::after` (`ask-ping`, a spreading `box-shadow` — not `scale`, which would stretch a 520×50 ring into an oval), and flips `.ask-pill-send` to `--glow-ink` (`ask-send-glow`). Both pseudo-elements are absolutely positioned, so they are not flex items of the pill, and the pill's own border stays the resting hairline underneath. The driver (`askAttract()`, next to the pill's click handler in both files) shows it **once per session** (`sessionStorage.askPillNudged`, so finsynth → case navigation doesn't re-nudge) and **never to someone who has already used the chat** (the shared `localStorage.askIntroSeen`); hover, focus, or opening the drawer cancels it early, and a 7s timer clears the class. Under `prefers-reduced-motion` the CSS drops the animations and holds the border lit instead — the hint survives, the pulsing doesn't — and that same timer is what puts it away. `index.html` has no pill, so it has none of this.

**Ask-me resize & pop-out:** The drawer's left edge is a drag handle (`.ask-resize`, keyboard: arrow keys on the focused separator) — width lives in `--ask-w` on `:root` so the page squeeze tracks it 1:1 (`body.ask-dragging` kills transitions mid-drag; JS clamps width to 300–720px, leaving ≥380px of column in squeeze mode). A header button (`.ask-head-pop`) toggles Zoom-style pop-out: `.ask-drawer.pop` + `body.chat-popped` turn it into a floating rounded window positioned by `--ask-x`/`--ask-y`, dragged by its header, right-edge-pinned when resized, clamped fully on-screen; the squeeze and rail-hide apply only to pane mode (`.chat-open:not(.chat-popped)`). Geometry persists in `localStorage.askPane`, shared by both chat pages. Below 700px the handle and pop button are hidden and a popped window auto-docks on resize; below 560px the drawer is full-width. `case.html` and `finsynth.html` each carry a copy of this — keep them in sync.

**Ask-me intro & section-aware chips:** Opening the drawer on an empty log runs `askIntro()`: a short `ASK_INTRO` orientation message — streamed word-by-word the very first time (`localStorage.askIntroSeen`, shared across both chat pages), rendered instantly on later opens so the log never starts empty; chips render after it. On `finsynth.html` only, the suggestion chips follow the reader: the section-rail tracker broadcasts the active chapter (`window.__askSection` + an `asksection` CustomEvent on `document`), QA entries carry `s: [section-ids]` tags, and `chipPool()` puts entries tagged with the current section first, padded with seeds. The `asksection` listener re-renders chips only when the drawer is open and not mid-answer (`ask.busy`), and `renderChips(keepScroll)` skips identical re-renders (`lastChips` key) and skips `scrollLog()` for section-triggered updates so page scrolling never yanks the chat log. `case.html` has the intro but not section chips (its chapters have no rail to track); its chips are just `c.qa` in order.

**Work cards:** `#work` has a two-tab toggle (`.work-tabs`, ARIA tablist with arrow-key support): "Work" (`#panel-work`, four cards: **FinSynth AI — Product** → `finsynth.html`, **FinSynth AI — Landing page** → <https://finsynth.ai/> in a new tab, **Mazic** → the Framer case study in a new tab, **Event Beep** → `case.html?c=eventbeep`) and "Side projects" (`#panel-side`, vibe-coded projects like Animation Curator, plain external links). Both panels are `.cards` grids toggled via `hidden` (`.cards[hidden] { display: none; }` beats the class's `display: grid`). Active tab gets `aria-selected="true"` + a 2px underline via `::after`.

The card itself is the site's only card, and it is kept inside the design direction: hairline `--line` border, 14px radius, page ground, **no** shadow at rest, no gradient, no photography. Structure is `.card` → `.card-art` (16/9 plate holding one `.card-mark`) + `.card-foot` (`.card-title` with a right-aligned `.card-arrow`, then a one-line `.card-sub`). Hover mirrors `.row` exactly — fills to `--bg-hover`, border to `--line-strong`, `--shadow-row` — and `.card-arrow` uses `.row-arrow`'s width/opacity/translate transition on the same `.35s cubic-bezier(.22,.61,.36,1)`, so the grid and the rows below read as one family. **The mark is type, not a logo**: the project name as a lowercase slug with the slash in `--faint` (`<i>/</i>finsynth`), because none of these products has a mark to show and a stock glyph would be decoration standing in for content — if real artwork ever arrives it replaces `.card-mark`, not the layout. One column below 640px (art goes 5/2, arrow hidden — there is no hover on touch, and the whole card is the target).

**Experience:** `#experience` is the old merged work list, unchanged and now under its own label — `.rows` with employment (FinSynth AI, Scream, Event Beep, with `.row-years`) and Scream's three products nested as `.row-sub`. The cards are for browsing the work, the rows are the chronology — they overlap on FinSynth and Mazic and diverge everywhere else. **The rows are the only route to `case.html?c=scream|yomo|slyce`**: those three have written case pages but deliberately no card, because there is no work to show in a tile for them (Ritika, 2026-08-20). Don't "fix" that by re-adding cards — give them something to show first.

**Animation Curator:** `animation-curator/` is build output from the sibling repo `../Animation curator` (Vite/React) — don't hand-edit it. To update: `npx tsc -b && npx vite build --base=./` there, then re-copy `dist/` over `animation-curator/`. Its effects load images from the site root, so `assets/img/` and `assets/video/` mirror that repo's `public/assets/`.

**Riri wordmark:** The header brand (`.nav-name` in all three files) is an inline SVG logo (`.riri-logo`) — "riri" hand-drawn in `--logo` purple via `currentColor` (viewBox 168×68), 28px tall, slight scale-up on hover. The r's are rounded monoline strokes. The **first i is a plain dotted stem** (circle at cx 57 + stroke-12 stem) — only the **second i is a sitting cat**: a filled eared-head path as the dot, a filled teardrop body as the stem (both in a `transform="translate(0 2)"` group so the head meets the neck), plus a stroke-7 tail (`.riri-tail`) sweeping right. There is no trailing asterisk. On hover/focus of the link the tail swishes: `@keyframes riri-tail-wave` morphs the path `d` through three shapes where `@supports (d: path(...))` holds, and `riri-tail-wag` rotates it from its base (`transform-box: fill-box`, origin `0% 0%`) as the fallback; both are inside `prefers-reduced-motion: no-preference`. If you retune the tail's `d`, update the 0%/100% keyframe to match or it will jump on hover. The link keeps the full name in `aria-label`. The three copies of the SVG and its CSS must stay identical — edit all of them. The footer copyright and `<title>` still spell out "Ritika Shakkerwal".

**Sections:** Hero → Work (`#work`, card grid, tabbed with Side projects) → Experience (`#experience`, rows) → About → Education (`#education`) → Toolkit → Footer/Contact. Nav anchors: `#work`, `#about`, `#contact`.
