# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Development

No build step — this is a static site of three self-contained pages. Serve locally with:

```bash
python3 -m http.server 8766
```

Then open `http://localhost:8766/`.

The only builds in the repo are the **two dev-only React islands**, and neither touches the site — `npm run islands` builds both, or one at a time:

```bash
npm run dial        # tuning panel      → assets/dial/dial.js              (index.html only)
npm run agentation  # annotation toolbar → assets/agentation/agentation.js  (all three pages)
```

Each is a self-contained ES module that its pages fetch **only** on localhost or behind a query flag (`?dial`, `?agent`) — see **Tuning panel** and **Annotation toolbar** at the end of this file. The three pages stay hand-written, and a real visitor still downloads no framework, bundler, or runtime: measured from a non-localhost host with no flag: zero island bytes on all three pages.

## Architecture

Three pages, each with its HTML, CSS, and JS inline — no framework, bundler, or runtime dependency; the only external request is the Inter webfont from Google Fonts (`finsynth.html` also loads Caveat for the problem wall).

- `index.html` — the portfolio itself: hero, work rows, about, education, toolkit, contact. Home of the interactive cat and paw prints.
- `finsynth.html` — the long-form FinSynth case study, with its own section rail, figures, and ask-me chat.
- `case.html` — one template that renders a short case study from `?c=<key>`, in finsynth's shell. It **holds exactly one key today, `eventbeep`**; it is a template with one entry, not a five-page section (see **Case studies**).
- `locked.html` — a password-protected case study in the same shell, and the one page here that is **generated rather than hand-written** (see **Password-protected case page**). Wherever this file says *the three files* about a shared shell block, `locked.html` is a fourth copy of it.

`finsynth.html` is the reference implementation of the shared shell (nav, masthead, chapters, close, reveal, theme, ask-me chat) and `case.html` carries a copy of it — when the shell changes, change both.

**Design direction:** Deliberately minimal, in the spirit of salleedesign.com — single 660px column, left-aligned, hairline rules between rows, near-monochrome palette, type doing all the work. No shadows, gradients, or decorative graphics. Keep it that way: new sections should be a `.rows` list or a `.pairs` definition list, not a new visual pattern. There are exactly **three** exceptions, all deliberate and all listed below: the `.shelf` card rails in `#work` / `#side` — tinted plates and photography, added because the work itself deserved tiles — the **section-label folder** (`.sec-icon`), a shaded Finder glyph beside each `.sec-label`, and the **photo blocks** in `#community` / `#life`, added 2026-08-22. Everything else stays rows, and none of the three is a licence for a fourth: a new decorative graphic still needs to be argued for. Note what the third one is *not*, which is decoration — in all three photo places the picture **is** the content, which is the same argument that earned `.card-art.shot` its screenshots: the mentoring sessions and the life outside the work are the only thing either section has to show.

**Type scale:** Six roles, and six is the point (Ritika, 2026-08-22: "define h1, h2, h3 and body1 and body2, pill. currently the text type the page still feels broken."). Across the three pages there were **seventeen** distinct font-sizes in play — 10, 12, 12.5, 13, 14, 15, 16, 17, 18, 19, 20, 21, 23, 24, 26, 30, 32 — which is not a scale, it is a pile, and it is why the type read as broken. Two of those were structural rather than just noise: `h2` was declared at both **26px and 32px**, and `.decision-head h3` at **26px** — the same size as the smaller `h2` — so wherever the two met the heading hierarchy was inverted and 07's three decisions read as peers of the chapters instead of children of one.

The tokens live in `:root` and the block is **identical in all three files**, so a heading is the same size on every page:

```css
--h1: clamp(32px, 7vw, 44px);   --h1-lh: 1.16;    /* page title */
--h2: 30px;                     --h2-lh: 1.28;    /* section / chapter title */
--h3: 22px;                     --h3-lh: 1.4;     /* sub-head, pull, card title */
--body1: 17px;                  --body1-lh: 1.7;  /* reading prose, standfirst */
--body2: 15px;                  --body2-lh: 1.55; /* UI, meta, captions */
--pill: 12px;                   --pill-lh: 1;     /* mono micro-caps tags and keys */
```

Three rules come with it. **Each role ships its line-height alongside** — a size without its leading is half a decision, and that is how 22px leading ended up on 13px, 15px and 17px text alike. **Anything needing a distinction the six can't make reaches for ink or weight, never a seventh size** — that is the chapter-head rule ("the head carries four levels on two type sizes, because colour and the rule do the rest") generalised to the whole site; it is also why the old 13px and 15px tiers collapsed into one `--body2`. And **the scale steps down as one thing, not rule by rule** — one media query, the same in all three files, replacing the per-rule mobile sizes that `.standfirst`, `.decision-head h3` and `.evo-hinge p` (a class since deleted — see **Before/After switcher**) each carried:

```css
@media (max-width: 720px) { :root { --h2: 26px; --h3: 20px; } }
```

`--h1` needs no entry there because its own `clamp()` already steps it, and `--body1`/`--body2` hold at any measure.

**One role moved, on 2026-08-23: the masthead `.standfirst` came off `--h3` and onto `--body1`** (Ritika, pointing at finsynth's: "its description, use different typography size. reduce it."). At 22px — the sub-head/pull tier — three lines of explanation competed with the `--h1` above them; it is a description of the product, not a second headline. Stepped to 17px it is reading-size prose, and the distinction from the body copy that follows is carried by **ink** (`--muted`) rather than by a size, which is the scale's own rule rather than an exception to it. Two things came with the step: the `letter-spacing: -0.2px` went, because it was tuned for 22px type, and the measure is capped at **54ch** — 17px across the full 660px column runs to ~92 characters, and at 54ch it holds the two or three lines a standfirst should be. `--h3` is untouched and still serves `.decision-head h3`, `.pull`, `.give-title` and `.card-mark`, which is why the token comment now reads *sub-head, pull, card title*. Changed in **`finsynth.html` and `case.html` together** — the standfirst is part of the shared masthead shell, and finsynth is its reference implementation.

**Artwork is off the scale on purpose** and is commented as such at each site, so a future scale bump can't resize a mock's UI: the pixel cat, the `.paw` prints, the `.row-tile` monogram (10px type sized to a 20px tile, the way the cat is sized to its grid), the Caveat handwriting on `.voice p` and `.wall li`, the fake browser chrome (`.fiag-window`, `.fiag-crumb`, `.slot`), and `.ask-avatar`. (`.product-frame .asset-stage p` was on this list until 2026-08-23, when the last placeholder stage was filled with a real capture and the rule went with it; `.slot` is now dead CSS with no markup using it, kept because it is the ready-made "screenshot missing" placeholder and the `--dia-box` comment names it.) `.card-mark` is the near-miss worth naming: it is a monogram like `.row-tile` but it sits **on** the scale at `--h3`, because a card plate is 272px wide and the mark is reading-size type there rather than a glyph fitted to a tile. One functional exception too: `.ask-input` stays hardcoded at **16px**, which is the iOS zoom-on-focus guard, not a type choice.

One knock-on worth knowing: raising the row role from 13px to `--body2` made `.row-static .row-role` overflow — the longer Education line came up ~8px short and clipped to "later alumni men…". The divider is filler on a static row where the role *is* the content, so it gives up the width (`.row-static .row-divider { min-width: 8px; margin: 0 12px }`) rather than the role getting a size of its own.

**Animation:** No animation library. Sections tagged `.reveal` fade up once via an `IntersectionObserver`. Everything else is CSS transitions. `prefers-reduced-motion` disables the reveal and smooth scrolling.

**Interactive cat:** A `position: fixed` SVG cat element tracks the cursor. It's a kawaii pixel-art "sprout kitty" — each of its four states (`sitting` front-facing, `chasing` side-profile stalk, `fleeing` stretched run, `caught` happy closed-eyes purr) is a 32×32 character grid passed to `pxSvg()`, rendered as 2px `<rect>`s in a 64×64 viewBox with `shape-rendering: crispEdges`; colors live in the `PAL` map. Animated parts (sitting tail, hearts, fleeing legs) are mini-grids rendered via `pxRects(rows, ox, oy)` inside classed `<g>` groups appended after the main grid — if you move them, update the matching `transform-origin` in the CSS (`.cat-tail-sit`, `.cat-legs-flee`). State changes swap `innerHTML` entirely. The cat chases when the user is scrolling, flees when the mouse moves fast within 250px, and sits otherwise. If the cursor lands on it (or it's tapped/clicked), it's `caught`: it purrs with a doodle speech bubble (`.cat-bubble`, a separate fixed div that tracks the cat) saying “Purrrr”, then wriggles free after 3s with 1.5s of catch immunity. This is the one intentional bit of whimsy — keep it intact across redesigns.

**Paw prints:** A pooled set of 24 `div.paw` elements (plus 4 cat emoji elements) are recycled via index cycling. They spawn on click and on hover over interactive elements (throttled to 2.5s), suppressed while scrolling. The hover selector lists the interactive classes — update it if row/link class names change.

**CSS custom properties** (in `:root`): colors and the font stack. Every color is a variable — that is what makes the dark theme below a single token block instead of a second stylesheet. Never hardcode a color in a rule; add a token.

**Light / dark theme:** All three pages ship both themes. A tiny inline `<head>` script (before `<style>`, so there is no flash of the wrong theme) resolves `localStorage.theme` — else `matchMedia('(prefers-color-scheme: dark)')` — into `data-theme="light|dark"` on `<html>`. Because of that, each file needs exactly **one** `:root[data-theme="dark"]` block right after `:root` (no duplicated `@media (prefers-color-scheme)` palette, and no `light-dark()` — its invalid-at-computed-value fallback is a trap). The driver JS is the first IIFE of the main `<script>`: it wires the header `.theme-switch`, updates `meta[name=theme-color]`, and follows the OS *only* while no explicit choice is stored. `localStorage.theme` is shared, so a choice made on any page holds on all of them — keep the head script, the driver, and the switch markup identical in the three files.

**The toggle is a switch pill, and it was a standalone icon button** (Ritika, 2026-08-23: "Add a switch pill instead of a standalone"). The button showed one glyph, which said nothing about state: you had to already know that a sun meant *you are in light* rather than *click for light*. `.theme-switch` is a 56×30 pill on `--switch-track` holding **both** glyphs with a 24px knob parked under one of them — so the mark the knob sits on is the theme you are in and the mark beside it is the theme you'd get, and the state is visible without reading the label. It shipped at 48×26 with a 20px knob and was scaled up on 2026-08-23 (Ritika, annotating the toggle: "increase the size") — everything scaled together, not just the box: knob 20 → 24, glyphs 13 → 15px, glyph margins 5.5 → 6.5px, so the glyph centres (14 and 40 inside the content box) still sit exactly under the knob's two parked positions; retune one of those numbers and the other three move with it. The knob moves on `translate` alone (`translate: 26px 0` under `:root[data-theme="dark"]`), which is compositor-only, so a theme flip can never reflow the header; colours still don't transition anywhere on this site, so only the travel and the border animate, and `prefers-reduced-motion` drops the travel. Both glyphs are **monoline strokes** — the moon used to be a `fill` in `finsynth.html`/`case.html` (a third, undocumented drift between the three copies) and at that size a filled crescent read heavier than the stroked sun beside it, so the inactive half looked like the active one.

Two things about how it's coloured. It needs a raised ground and a knob that reads **lighter than the track in both themes**, and the three files name their raised surface differently (`--bg-secondary` on `index.html`, `--bg-raised` on the case studies) — so each file aliases **`--switch-track`/`--switch-knob`** once per theme in its own `:root` blocks, and the `.theme-switch` CSS below is then byte-identical in all three (verified: same MD5). Add a page and it needs the two aliases, not a new rule. And it is a real **`role="switch"`**: `aria-checked` is *dark is on* and the driver keeps it in step, the accessible name is fixed (`Dark theme`) rather than rotating, and the `title` names the theme you'd get — an icon-only control has to supply its name, same rule as the footer marks.

Tokens split three ways, and the split is the whole design:
- **Page furniture flips** — `--bg`, `--bg-card`/`--bg-raised`/`--bg-stage` (finsynth) / `--bg-secondary` (index), `--text`/`--muted`/`--faint`, `--line*`, `--brand`/`--logo` (both lift to `#a97bff` on near-black, where `#752afc` vibrates), `--fail`, `--ok`, `--ask-pill-bg` and the `--glow-*` set (the ask pill's surface and its attract ring), `--print-well` (the well inside a `#life` polaroid — see **Beyond work**), and the `--dia-*` diagram ink (drawn figures are only ink on the page's own ground, so they invert with it).
- **Artwork never flips** — the pixel cat, the pale `--note-*` sticky notes and the `--gray-*` ramp they're written in, the blush `--chrome-*` browser frame, the `--art-bg/-ink/-muted/-line` set behind it, `--blue-core` (the mat, the favicon, the "better way" note), the traffic lights, the mat shadows. A light product screenshot must not end up framed in half-dark chrome, and a negative of a face or a sticky note reads as a glitch. `--blue-ink` exists purely so diagram blue can flip while `--blue-core` stays put; `.paw-cat` exists so the paw prints can invert while the emoji cats only brighten. The **one** piece of shaded artwork that *does* flip is the `--folder-*` set (see **Section icons**) — it is a glyph standing next to a `--faint` label rather than a photo or a face, and held at its light values it was the brightest thing on the dark page, shouting over the word it introduces. Same material in both themes; only the values step down.
- **Shadows are per-theme** (`--shadow-row/-pill/-panel/-drawer/-pop/-note`): a soft black blur does nothing on a dark page, so the dark set is deeper and tighter. Surfaces that need to lift off near-black use `--bg-float` instead of a shadow (the ask drawer/pill/chips) — `--bg` there left them indistinguishable from the page behind.

Colors deliberately do **not** transition — a color transition would collide with `body { transition: padding-right }` during the chat squeeze.

**Row hover:** `.row` replicates salleedesign.com's work-row interaction — the row fills into a white pill, `.row-role` slides open (`max-width` 0 → 100%), `.row-end` opens its `column-gap` 0 → 12px, and `.row-arrow` eases in (`width` 0 → 16px, `translateX(14px)` → 0), all on `.35s cubic-bezier(.22,.61,.36,1)`. Below 640px there is no hover: the role is always visible and the arrow/divider are hidden. `.row-static` rows (Education) never light up and always show their role.

**Section rail:** `finsynth.html` only (`.index`, fixed in the **top-left corner of the viewport** at `top: 168px; left: 32px` — top-aligned, not vertically centred, and anchored to the window rather than computed off `--content`/`--gutter`, so it stays parked while the column recentres; hidden below 1120px where the margin can't hold it) — `case.html` has a different rail, the tick rail below. No header and no numbers: one `<a>` per chapter hanging off a **continuous hairline rail** (`ol { border-left: 1px solid var(--line) }`), with the active chapter's segment inked in — `a::before` is a 1px bar at `left: -1px` spanning the row, `--text`, `scaleY(0)` → `scaleY(1)` for `aria-current='true'` on `.28s cubic-bezier(.22,.61,.36,1)`. It is `scaleY` from a top origin rather than an animated `height` so a chapter change stays on the compositor and can never reflow the rail. Inactive labels are `--muted` (not `--faint` — an inactive item still has to be readable) and go `--text` on hover. `li.sub` (the three decisions inside 07) steps only the *label* in; the inked segment stays on the one shared rail line. An earlier version replaced the rail with a per-chapter horizontal tick under a `Table of Contents` header — reverted on purpose; don't bring it back. `aria-current` is set by the scroll tracker (the same one that broadcasts `asksection` to the chat), so the rail and the suggestion chips always agree on which chapter you are in.

**The rail sits at 168px, and it was written at 92 (2026-08-23).** 92 cleared the 81px header and nothing else, which was the whole story until the story-tab band went full width: the band sticks flush under the header and now runs the full viewport, so it passes *beneath* the rail and ends at 148. The rail lives outside `main`'s stacking context (`main { position: relative; z-index: 1 }`, `.index` is a sibling at z-index 50), so it always paints **above** the band — which meant the band's bottom shadow drew a faint line straight through the first two labels. Two other fixes were considered and rejected: the `rail-peek` `--bg` halo idiom would notch the band's shadow rather than hide the collision, and dropping the band's shadow would take away its only separation from the content scrolling under it. So the rail clears the band the same way it always cleared the header, one surface later: 148 + 20. Retune `.story-tab-sticky`'s `top` or padding and this number follows it.

**The shadow that forced that move is gone, and 168 stays** — the band is still 67px of opaque `--bg` parked at 81, so a rail at 92 would have its first two labels *behind* a bar rather than merely crossed by a hairline. The collision the shadow caused was the symptom; the band passing beneath the rail is the cause, and only the cause sets the number.

**Opening story tabs (`finsynth.html`):** The four opening chapters — 01 The analyst, 02 The problem, 03 The product, 04 The limitation — share one sticky navigator (`.story-tab-sticky` → `.story-tablist` → four `.story-tab`s) above them, and each chapter carries `class="story-tab-panel" role="tabpanel"`. **It is a navigator, not a real tab set:** nothing is ever hidden, the four chapters stay in one continuous scroll sequence, and a click just `scrollIntoView`s its panel. So the reader who scrolls past it never loses a chapter, and the reader who wants to jump gets four addresses in one control. The driver (its own IIFE, next to the ask-cat one) sets `aria-selected` from an `IntersectionObserver` on the four panels (`rootMargin: '-120px 0px -55% 0px'`), so the band tracks the scroll the way `.index` does; a click also `history.replaceState`s the hash, and the four `.index` links to those chapters are intercepted to run through the same `activate()` so the rail and the band can never disagree. `.story-tab-panel { scroll-margin-top: 168px }` is what keeps a landing clear of the header plus the band — it beats `.chapter`'s own 76px on source order, not specificity, so don't move either rule above the other. Measured: every one of the four tabs lands its chapter at `top: 158` against a band bottom of 148. The 10px is `.reveal`'s `translateY(10px)`, still in flight when `scrollIntoView` measures the box; the clearance is what matters and it is positive at every tab.

**The band is full width, and it was column width (Ritika, 2026-08-23: "this needs full width.. but also still its not fully visiblt so lower a bit").** Two complaints in one sentence, and the second is what forced the first: the band was a 660px strip sitting on the reading column, so it read as a floating pill rather than as a second bar, and at `top: 0` it tucked under the sticky header. It is full-bleed now with **`.wf`'s own idiom** — `margin-inline: calc(50% - 50vw)` against `width: auto`, with the gutter restated as padding — so it grows to exactly 100vw without ever naming `100vw` (`docScrollX` stays 0 at 1698, 1440 and 390), and it sticks at **`top: 81px`**, the header's height. Nothing new was drawn: the ground is `--bg` and the only addition was a bottom shadow, the band's separation from the content scrolling beneath it. That shadow is also what moved the chapter rail down — see **Section rail** above.

**There is no shadow now, stuck or not (Ritika, 2026-08-23: "dont already have a shadow and all.. only when it sticks to top", then "no need of shadow").** Two notes, and the first one was implemented before the second arrived: the shadow moved onto an `.is-stuck` class that a scroll-and-resize watcher toggled, so a band sitting in flow above the chapters was flat and a band parked under the header lifted. Her second note declines the lift altogether, and the band does not need it — its ground is `--bg` and fully opaque, so nothing shows through it, and the blue active segment is what says *this is a bar*. What went is a hairline of depth, not the bar. **The class went with the shadow**, and so did its watcher, its `transition`, and its `prefers-reduced-motion` override: nothing in the file reads `.is-stuck` now, and re-adding a stuck state means re-adding all four.

**The active segment is filled blue and set bold (Ritika, same round: "switch colour need to be \" blue\" and highlight or bold the text").** It was `--bg-raised` under `--text` ink, which is the quiet lift `.evo-tabs` uses, and in a full-width band that quiet was the problem: nothing said which of the four you were reading. `--blue-ink` is the blue this page already owns, so no token was added. The label takes **`--bg`, not a fixed white**, so it stays legible on both of that token's values (near-white on `#345bc3` in light, near-black on `#7f9dff` in dark). And bold costs no width here because `--mono` is a fixed-pitch stack: 500 → 700 cannot shift the four segments as the selection moves (measured `[139, 139, 139, 165]`, identical through a full cycle of all four tabs in both themes).

**03's head is one line, and it was two (Ritika, same round, on `#start h2`: "why 2 lines?").** It read `FinSynth already solved parts of the analyst's job.` — 677px against the 660px column, so it wrapped by 17px and was the only `h2` on the page that did. **`analyst's` is the word that went, not `already`:** chapters 01 and 02 are about the analyst and the tab above the head says so, while `already` is the word that sets up 04's limitation. One line at 1698 and 1440 (38px tall).

**Tick rail (`case.html`):** A chapter-progress rail on the **right** (`.case-rail`, fixed at `top: 50%; right: 32px`, `translateY(-50%)`) — one 34px tick per chapter, the one you're in inked and at full length (Ritika, 2026-08-22, from a reference image of right-aligned dashes with the last one bolder). Built by its own IIFE after the renderer, since the chapters it indexes only exist by then: `<li><a href="#ch-N"><i></i></a></li>` per `main .chapter[id]` — the renderer emits `id="ch-<n>"` for exactly this.

**Ticks, not labels, and that is the difference from finsynth's `.index`.** A short case study's chapter names are two words each (`Context`, `What I worked on`, `What I learned`), so a 168px labelled list in the margin would out-weigh the three-section page it indexes; the tick says *where you are* and nothing else. It is **not** the per-chapter horizontal tick that was tried on `finsynth.html` and reverted — that one replaced a labelled rail that was working, under a `Table of Contents` header; this page never had a rail at all. And it is **vertically centred** rather than parked in a corner like `.index`: with no labels there is no reading order to align to the masthead, so the rail sits where the eye is. Icon-only links, so each `<a>` carries both `title` and `aria-label` with the chapter's `h2` text (through `esc()`, which escapes `& < > "`) — same rule as the footer marks.

The tick keeps **one box in every state and only ever scales**: `2px` tall at `scaleX(.6) scaleY(.5)` inactive → `transform: none` for `aria-current='true'`, `transform-origin: 100% 50%` so it grows leftward, away from the page edge. Transform-only for the same reason `.index` animates `scaleY` and not `height` — a chapter change can never reflow the rail. `scaleY(.5)` on a 2px bar lands on a crisp 1px. Inactive is `--line-hover` because `case.html` has no `--line-strong` token; `--faint` on hover, `--text` active.

`aria-current` uses the **same test as `.index`** — the last chapter whose top has crossed 42% of the viewport, plus a bottom-of-page pin because the closing chapter is short — rAF-throttled on scroll and resize, so the two shells agree on what "current chapter" means. The nav ships `hidden` and empty and is only unhidden after a successful build, so **"Case not found" and any single-chapter case get no rail** (`targets.length < 2`: one tick is a dot, not a position gauge). It fades out with `pointer-events: none` under `body.chat-open:not(.chat-popped)` — the docked drawer owns the right edge; a popped-out window leaves it alone. Hidden below **1024px** (not `.index`'s 1120px — 34px of tick needs far less margin than a labelled list), and reduced motion drops the transitions and the fade-in but keeps the ticks. `finsynth.html` has `.index` and none of this.

**Spotlight reveal:** A hidden photo revealed through a soft-edged lens that trails the cursor. **Exactly two places have one** — `index.html`'s hero and `finsynth.html`'s masthead. The short case studies deliberately have none: `case.html` contains no `.spotlight` markup, CSS, or driver at all, because a photo behind that column fought the copy. Don't add one back. Each `.spotlight` layer (absolute, `inset: 0`, `pointer-events: none`, `overflow: hidden`) holds a fixed-size `.spotlight-lens` (760px, radial-gradient `mask-image`, moves via `style.translate`) containing a `.spotlight-img` sized to the host from JS and counter-translated each frame so the photo appears pinned while the lens roams. The image lives in `:root` as `--spotlight-hero-img` (`assets/spotlight-hero.jpg`) — a real photo, chosen to hold color edge-to-edge. The driver IIFE (end of the script) arms `layer.parentElement`: snap + fade in on `mouseenter`, lerp (0.09) on `mousemove`, fade out on `mouseleave`; the rAF loop stops when settled. Disabled by both CSS and JS under `prefers-reduced-motion`, `hover: none`, or ≤640px. Keep it below z-index 60 (header) and never at/above 9997 (cat band); hero copy sits above it via `.hero .wrap { z-index: 1 }`. `finsynth.html` carries its own copy of the same CSS + driver on its masthead (`.masthead-band` hosts the layer; image in `--spotlight-img`, a b&w Wall St photo at `assets/finsynth/spotlight-wall-st.jpg` (any spotlight image must hold tone edge-to-edge — one that fades to white reads as an empty lens)) — keep the two implementations in sync if the interaction changes. The **one deliberate divergence is the ink lens below**, which `index.html`'s hero does not have.

**Ink lens (`finsynth.html` masthead only):** Whatever masthead copy falls inside the spotlight circle flips to the *opposite* ink — white in light theme, near-black in dark (Ritika, 2026-08-23, annotating `.masthead-facts`: "when i hover in light mode against this, turn the text which ever come sunder the hover effect circle area, into white, and vice versa for DARK MODE"). Two tokens carry it, one pair per theme: `--spot-ink` (`#ffffff` / `#0e0e12`) and `--spot-ink-halo` (`rgba(0,0,0,.62)` / `rgba(255,255,255,1)`). The halo alphas are **deliberately asymmetric** — see **The dark half was illegible** below.

**It is a masked clone, because CSS cannot recolour type by cursor position** — no selector addresses "the glyphs currently under a circle". So the driver clones `.masthead` into a `.spotlight-ink` layer laid pixel-exactly over the real copy, paints the whole clone in `--spot-ink`, and masks it with the same roaming circle; the real copy underneath is never touched, and outside the circle it is the only thing visible. `mix-blend-mode: difference` was the alternative and it is wrong here: it would invert the *photograph* into a negative, and artwork on this site never inverts.

Six things about it are load-bearing:
- **It reuses `.spotlight-lens`.** The ink lens is pushed onto the same `lenses`/`stages` arrays the photo lens rides, so both circles share one `x`/`y`, one `on` class and one translate — they cannot drift apart, and the whole effect stays transform-only on the compositor. Its mask is the one thing that differs (a tighter `66% → 84%` falloff, because a glyph edge needs a harder cut than a photograph does; it shipped at `46% → 74%` and that band was most of the dark-theme bug below).
- **It is placed by measurement, not by matching padding.** `size()` reads `.masthead`'s own rect against the layer's and writes `left`/`top`/`width` onto the clone — `.masthead` pads 80/92 and the hero figure breaks out past the column, so no reconstructed offset would land. `resize` re-runs it.
- **It is built lazily, on first `mouseenter`** (`buildInk()`), so the page load pays nothing and the clone's hidden `<img>` costs no request (the hero shot is cached by then). `.spotlight-ink-copy .hero-product { visibility: hidden }` — hidden, not removed, so the clone keeps the figure's height and every line below it stays aligned with the real copy.
- **The clone must never be reachable twice**: `aria-hidden`, `pointer-events: none`, `user-select: none` (a select-all would otherwise copy the masthead twice), and every `id` stripped in JS.
- **The dark-theme masthead lift is scoped through `> .wrap`.** Those rules ink the real copy up over the Wall St plate; unscoped they also matched the clone, whose entire job is to be the opposite ink. Rename `.wrap` there and the two fight.
- **The halo is not decoration.** White glyphs sat invisibly on the near-white top of the b&w plate, so `.spotlight-ink-copy` carries a three-stop `text-shadow` in `--spot-ink-halo` — the same halo device the dark theme already used on this masthead, inverted. The radii are `1/3/10`, and they were `2/8/20`: what the facts grid needs is an **outline, not a glow**, because a 20px bloom spends its alpha out over the photograph instead of hugging the glyph, and the letter edge is the only place contrast is decided.

Clone colour rules are written **two classes deep** (`.spotlight-ink .spotlight-ink-copy h1`, `… dt`, `… span::before`, …) to beat every base rule that inks a part of the masthead: inside the clone there is exactly one colour. Killed with the spotlight under `prefers-reduced-motion`, `hover: none` and ≤640px — the layer is never built at all, so those readers get zero extra DOM.

**The dark half was illegible, and the fade band was the reason (fixed 2026-08-23, Ritika: "the text is not visible in herosection when dark mode and hovered").** Under the open lens in dark theme the facts grid sank into the photograph — `TEAM`, all three roster lines and the tail of `Product and Design (end to end)` unreadable, while the copy outside the circle was fine. The mechanism was working exactly as written; the failure was the **mask**. At `46% → 74%` more than half the circle's area sat at partial alpha, and a near-black clone at ~40% alpha over the real white copy underneath is neither ink: it is grey type on a grey photograph. Narrowing the band to `66% → 84%` is most of the fix. Two smaller things came with it: the halo radii tightened to `1/3/10` (above), and **dark's `--spot-ink-halo` went opaque** while light holds at `0.62` — the asymmetry is the photo's, since near-black type has to hold over the plate's mid-grey facade and its shadowed doorways (measured luminance p25 = 85 of 255) where white type in light theme starts from a much shorter fall. Same shared three-layer stack in both themes; per-theme strength is the token's job.

Four alternatives were rejected with reasons, so they don't get retried: a **per-theme mask** (dark measurably prefers 66/84, light marginally prefers 46/74 — not worth a second number for ~0.1 in the theme that was never broken), **`80% → 92%`** (the arc starts cutting visibly across glyphs, trading mush for a hard edge through the middle of a word), a **five-layer stack** weighted at 1px (at `--body2`'s 15px it reads as embossing, the halo filling the counters rather than ringing them), and **dropping the inversion in dark**, which contradicts the note that asked for it. And one process lesson is written into the CSS at the halo rule: **the call was made on 2× screenshots, not on a contrast metric.** A p10/p90 luminance ratio over each roster line ranked the five candidates backwards — it cannot tell near-black type with a light ring from light type with a dark ring, so it simply rewarded whichever put more range in the box.

Verified after: three shadow layers and the right token per theme, mask stops `["0%","66%","84%"]`, exactly **one** resolved colour in the clone in each theme (`rgb(14,14,18)` dark / `rgb(255,255,255)` light) across the **25** clone elements outside the hidden figure, clone geometry identical to the real `.masthead`, `docScroll: 0`, no page errors, and `inkLayers: 0` under all three kill conditions (reduced motion, `hover: none`, 390px). `finsynth.html` is the only file with any of this — `index.html` and `case.html` contain no `spotlight-ink` at all, so there is **nothing to keep in sync**.

**Loading animation:** `index.html` only — first paint is one pixel field across the **whole first screen** in **two inks**: the hero spotlight photo rises out of bricks in the side margins (outside the dashed column guides) while the content column is bricked in the page's **own ground tone**, a faint pixel shimmer with no photo behind the copy. Same grid, same landing beats, so it reads as one field rather than two effects. Two earlier versions were tried and rejected: margins-only left a flat strip down the middle that read as a hole in the effect, and running the photo wall-to-wall put a sunset behind the copy. The point of the two-ink split is that the *content* pixelates too — the copy is pixel-erased for about a second and comes back crisp when the field fades. Pixels first, deliberately (Ritika chose this over keeping the copy legible throughout). Adapted from the Animation Curator "Pixel Assemble" effect, with four deliberate departures: it **keeps the photo's colour** (the source drained it to grey, which is right for a b&w Wall St plate and wrong for a sunset), it **never resolves to the sharp photo** (the mosaic is the whole reveal — the sharp version is what the spotlight lens is for), it **plays once** instead of looping, and it is **brisk** — ~950ms to settle plus a 420ms fade, because an intro the reader is looking past should be over in about a second, not announced. `.loader` is a body-level `position: absolute` full-width div (z-index 10000, above the cat band at 9997) holding one canvas, with **no background of its own** — `draw()` starts with `clearRect`, not a ground fill, so the bricks assemble *over* the live page instead of on a curtain: the page is never hidden, only overdrawn, and because the element keeps `pointer-events: none` throughout with no scroll lock, every link is clickable from the first frame. **Absolute** rather than fixed so it scrolls away with the page if the reader moves before it finishes, and **body-level** rather than inside `.hero` so it can also cover the sticky header, which is opaque and which a child of `main` (`z-index: 1`) could never rise above. Its height is one `window.innerHeight` — the first screen, which is all the reader can see at load. The driver is the second IIFE in the script. One grid: `cols = round(vw / TILE)` (8px bricks), `cell = vw / cols`, rows filling the screen bottom-aligned. Which ink a cell gets is decided by its **centre** against `guides()`, which recomputes `body::before`/`::after`'s expression off the same `--content`/`--gutter` tokens, so the changeover lands exactly on the dashed guide; margin cells are sampled from one photo laid out `cover` across the full width (the middle is sampled too and simply never used, which is what makes the two bands read as one image behind the page), and column cells get `groundTone()` — the resolved `body` background jittered by `±JITTER` (9) per channel on a second, decorrelated `sin` hash (`seed2`, so the tonal noise doesn't stripe along the same lines as the landing order), signed by `LIFT` so bricks lift off a dark ground and sink into a light one instead of clamping flat at 0/255. Bricks land bottom-to-top on deterministic scattered beats (a `sin` hash, never `Math.random`, so the order is identical on every load), each dropping in from just above its slot and popping home with an ease-out-back overshoot, with a 0.75px bleed so sub-pixel cell widths leave no seams. `REVEAL_WINDOW` (0.22) is wider than the source's 0.16 because the short timeline would otherwise flick each brick into place too fast to read as a landing — shorten `ASSEMBLE_MS` further and it needs widening again. `MIN_BAND` (72px) suppresses **only the photo**, not the loader: below it the margins are slivers where a sunset would read as noise, so narrow windows and phones get the ground-tone field alone. Because that field needs no network, a slow or broken photo costs nothing — `IMG_CAP_MS` and `onerror` both call `start()` ground-only rather than dismissing (an empty rectangle was the old failure mode), and a photo that arrives after `started` is ignored so the ink never swaps mid-assembly. Once the last brick settles the mosaic **is** the wait state: it holds until `window.load`, capped at `WAIT_CAP_MS`, then fades out and the element **removes itself from the DOM** — nothing of it survives the load, and it adds nothing to layout while it lives (page `scrollHeight` is identical with and without it). Killed in CSS *and* JS under `prefers-reduced-motion`, same as the spotlight, so a reduced-motion reader never sees a frame. `finsynth.html` and `case.html` have none — a loader on every case-study navigation would be a tax, not a flourish.

## Tuning panel (dev only)

`dialkit` is a React panel, so using it meant a React decision. It was answered with a **React island over the tokens** (Ritika, 2026-08-22, choosing it over a full port): no markup became JSX, no page imports React, and the three files are still hand-written HTML with inline CSS and JS. React owns exactly one thing — a `<div id="dial-root">` appended to `<body>` at runtime — and all it ever does is *write* into two registries the page's own code already reads: the `:root` custom properties, and a plain `window.__tune` object. A full port was costed and rejected: ~7,700 lines of markup and ~3,700 of CSS, the loss of the no-build architecture, and the inline `<head>` theme script that is the only reason there is no flash of the wrong theme.

The alternative was never necessary because the design system was **already** the right shape for a dial — every colour is a `var()` (see **CSS custom properties**) and every animation number is a named JS constant. The island only had to reach them.

**Files.** `src/dial.tsx` is the whole island (four panels), `src/env.d.ts` declares the `?inline` CSS import and the two `window` additions, `vite.config.ts` builds it — **one island per build**, picked by the `ISLAND` env var now that there are two (see **Annotation toolbar** below). Output is `assets/dial/dial.js` — **gitignored build output, never hand-edited**, rebuilt with `npm run dial` (or `npm run dial:watch`). One file, one request: dialkit's stylesheet comes in with `?inline` and is injected from JS. Two things in that config are load-bearing and both were bugs first: `fileName: () => 'dial.js'` because the page hardcodes the import path and a content hash would break it every rebuild, and `define: { 'process.env.NODE_ENV': '"production"' }` because **Vite's lib mode does not substitute it** the way an app build does — React's dev guards survived into the bundle and threw `process is not defined` in the browser (19 live references), and fixing it also dropped the React dev build (1,264 kB → 615 kB, 151 kB gzip). That define turns dialkit's own dev check false, which is why `dial.tsx` passes `productionEnabled`; the URL gate below is the real guard, not `NODE_ENV`.

**The gate.** The last IIFE in `index.html`'s script arms the panel on `localhost` / `127.0.0.1` / `[::1]`, or on any host with `?dial` in the query — otherwise it returns before doing anything. Loading is a dynamic `import()`, which works inside a classic `<script>` and resolves against the document base URL, so a real visitor makes **zero** extra requests (verified: 10 requests un-gated, 12 with `?dial`) and a missing bundle is a one-line `console.warn`, not a broken page. `index.html` only — `finsynth.html` and `case.html` have no panel and no gate.

**Two invariants in `dial.tsx`, and both matter.** First, **a dial at its default writes nothing** — `put()` compares against the shipped value and calls `removeProperty`, so the stylesheet stays in charge of every untouched token. Pinning all of them at mount would have silently killed the light/dark flip, because an inline `style` on `<html>` outranks `:root[data-theme="dark"]`; as shipped, the toggle still round-trips with the panel open. Second, **dial names are token names** — so the panel's Copy button hands you JSON whose keys tell you which line of `index.html` to edit to make a value permanent. They are **camelCase** rather than the `SCREAMING_SNAKE` of the constants themselves, and that is forced: dialkit's label formatter splits runs of capitals, so `TILE` rendered as `T I L E` and `ASSEMBLE_MS` as `A S S E M B L E_ M S`. The loader block therefore maps `tile`/`assembleMs`/… back onto `window.__tune.loader`'s `TILE`/`ASSEMBLE_MS`/… in one `Object.assign` — rename a dial and that mapping is the line to change with it. A dialed value is a proposal; the source file is still the record. The `Clear overrides` action in Tokens wipes the inline styles back to shipped.

Two tokens can't be written to `:root` at all and are set per element instead: `--shelf-card` is declared on `.shelf` and the lens size on `.spotlight-lens`, and a custom property declared on a class cannot be overridden from an ancestor.

**`window.__tune`** is the first thing in `index.html`'s main script, ahead of the theme IIFE, and it is now the **single source of truth** for the loader, cat, paw and spotlight constants — each value sitting where it used to be declared, with its original comment. It is inert on its own: with no panel, the drivers read the same numbers they always did. It works live because those loops re-read it every frame or every event (`window.__tune.spot.lerp` inside the rAF lerp, `window.__tune.paws.hoverThrottle` per hover, `var K = window.__tune.cat` with every field read at use). Deliberately **not** dialed: the sitting friction `0.9`, the catch hysteresis (`half + 20` / `half + 4`), and the loader's `FOCUS_X/Y` and `IMG_CAP_MS` — hysteresis in particular is a pair of numbers whose *gap* is the feature, and a slider on either half invites breaking it.

The loader is the exception to "live", because it runs once at load and removes itself. So the IIFE became a named `runLoader()` plus a `window.__replayLoader()` that re-inserts the captured markup and calls it again, driven by a **Replay loader** action rather than a slider. Two fixes came with that: `__introRelease` now clears `window.__introHold`, or a replay would sit out the full 3.2s failsafe before drawing a brick; and `runLoader` stamps a `runId` against a module-level `loaderRun` counter, checked in `frame()` and in the resize handler, so a replay mid-flight supersedes the old run instead of two rAF loops drawing to one canvas (verified: replay-during-replay leaves exactly one `.loader`).

**Motion tokens.** `--ease-row`, `--dur-row` and `--dur-fill` were added next to `--content`/`--gutter` and replaced **12** longhand `.35s cubic-bezier(.22,.61,.36,1)` / `.3s …` declarations — the interaction this file calls one family was actually twelve independent numbers that only happened to agree. Same rule as colour: don't hardcode it, add a token. The refactor is behaviourally identical — a geometry-plus-computed-style diff of every element in `main`/`header`/`footer` against `HEAD:index.html`, at 1440/900/620px in both themes, reports **0** differences including resolved `transition-duration` and `transition-timing-function`.

**Four panels**, each with a stable `id` and `persist: true` (so values survive a reload): **Tokens** (brand, ink, ground, lines, ok, plus Clear overrides), **Layout** (`--content`, `--gutter`, `--shelf-card`, lens size, `--dur-row`, `--dur-fill`), **Animation** (the eight loader constants + Replay, spotlight lerp, paw throttle) and **Cat** (flee, chase, caught, edge padding).

**Rules.** Don't convert page markup to JSX — the island exists so that never has to happen. Don't ungate the panel or import it from the other two pages. And when a dialed value is the one you want, write it into the source line and reset the dial; don't leave the number living in `localStorage`.

## Annotation toolbar (dev only)

The second React island, and the only one on all three pages. [Agentation](https://www.npmjs.com/package/agentation) is a visual feedback toolbar: click an element, say what is wrong with it, and the note reaches the coding agent already carrying which element you meant — its path, its classes, the text near it. That is what earns it a dependency here; the alternative is describing "the third card's subtitle, the one under the plate" in prose every time. Ritika had it on the FinSynth landing page before this site (there it mounts plainly as `{import.meta.env.DEV && <Agentation />}` in `src/main.jsx`, clipboard mode, no endpoint).

It obeys the same rule as the dial: **React never owns page markup.** `src/agentation.tsx` appends one `<div id="agentation-root">` to `<body>` and renders `<Agentation endpoint="http://localhost:4747" />` into it — the component then portals its UI out to `<body>` and reads the DOM the three pages already rendered, so the host div stays empty and no hero, row or card became JSX. Its CSS is compiled into the bundle (its dist ships no `.css`), so like the dial it is exactly one file and one request.

**Why its own bundle rather than a fifth dial panel:** `dial.js` is `index.html`-only by design and the rule above it says don't import it from the other two pages — and the copy most worth annotating is on the two case studies. So `vite.config.ts` grew an `ISLANDS` map keyed by the `ISLAND` env var instead of a second Rollup entry (two entries in one pass make Rollup hoist the shared React into a third chunk, and each page hardcodes exactly one import path) and instead of `--mode` (a non-standard mode stops Vite resolving the build as production). That refactor is proven inert for the dial: `assets/dial/dial.js` comes out byte-identical, same SHA-256, 615.63 kB.

```bash
npm run agentation         # build it once
npm run agentation:watch   # rebuild on save
npm run islands            # both islands
```

**The gate** is the same shape as the dial's and lives at the end of each page's main script: `localhost` / `127.0.0.1` / `[::1]`, or any host with `?agent` in the query. The three copies are identical — **keep them that way.** Verified from a non-localhost hostname: 20 / 8 / 3 requests on index / finsynth / case with the toolbar absent, and exactly **three** more with `?agent` (the bundle plus the two calls to 4747). Index's 20 reconciles with the **10** the dial section measures — the other ten are `assets/life/*.jpg` and `assets/community/mentoring-*.jpg`, which `0743439` (*Add the Community and Beyond work sections*) references but never added, so they 404. **Ten missing photos, not an island problem** — drop the files in and the count returns to 10.

**The server is optional and that is the point.** `.mcp.json` registers `npx agentation-mcp server` at project scope, which runs an HTTP server on **port 4747** alongside MCP over stdio, so annotations arrive in Claude Code as they are sent (`agentation_get_all_pending`, `agentation_watch_annotations`, `agentation_resolve`, …; `agentation-mcp doctor` checks the setup). With it down the toolbar logs a refused connection to `/health` and `/sessions`, keeps every annotation in `localStorage`, and falls back to copying markdown to the clipboard — a forgotten server costs a paste, not the notes. Claude Code has to be restarted for `.mcp.json` to load.

**One known rough edge, on `index.html` only.** Agentation's `blockInteractions` covers `button, a, input, select, textarea, [role='button'], [onclick]` — which is every real control, but not this page's two document-level whimsies: clicking to place an annotation still spawns **paw prints**, and the **cat** keeps tracking the cursor while you aim. Nothing breaks and no annotation is lost; it is only noisy. Left alone deliberately rather than coupling the page's own JS to a dev tool — the fix, if it ever annoys, is to have the paw and cat handlers bail while `document.documentElement` carries Agentation's `data-drawing-hover`, which is the one root-level signal it exposes. `finsynth.html` and `case.html` have neither the cat nor the paws, so neither has the problem.

**Rules.** Same as the dial's: don't convert page markup to JSX, and don't ungate it. `assets/agentation/agentation.js` is **gitignored build output, never hand-edited**. The `agentation` setup skill (installed by `npx skills add benjitaylor/agentation` into both `.claude/skills/` and `.agents/skills/`, alongside `agentation-self-driving`) is Next.js-only (it edits `app/layout.tsx` / `pages/_app.tsx`) and does not describe this site — the island above is the install here, so don't let that skill re-do it.

## Password-protected case page

`locked.html` holds a case study that cannot be published in the open. Ritika's brief was specific about what it must not be: *"Do NOT give me a simple JavaScript if/else password check, because that can be bypassed via View Source."* That constraint is what shapes everything below, and it is met **structurally rather than by hiding a comparison better**.

The page carries one **AES-GCM-256 ciphertext** and no password. AES-GCM is authenticated, so its 128-bit tag is verified as part of decryption: a key derived from the wrong password makes `crypto.subtle.decrypt()` reject. "Wrong password" is therefore a caught exception, not a branch a reader can find in the source and step over, and **patching the JS gets you nothing, because the plaintext is not in the file to be revealed.** The key comes from **PBKDF2-HMAC-SHA-256 at 600,000 iterations** (the OWASP floor) over a 16-byte random salt, with a 12-byte random IV.

**It is a generator plus a template, not a hand-written page, and that is forced by the one rule that matters here: the plaintext must never be committed.** A single hand-authored HTML file cannot satisfy that, because someone would have to paste the secret into it to encrypt it.

- `tools/encrypt-case.mjs` — the offline encryptor, run as `npm run lock`. It prompts for the password twice on a muted readline (or reads `CASE_PASSWORD` for CI), refuses anything under 12 characters or obviously weak unless you pass `--allow-weak`, and substitutes five placeholders into the template: `__PAYLOAD__`, `__TITLE__`, `__HEADING__`, `__STANDFIRST__`, `__HINT__`. A missing placeholder is an error, not a silent pass.
- `tools/locked.template.html` — the shell plus the gate, with the payload slot.
- `private/` — where the plaintext lives, **gitignored**. The encryptor's own last line says so: "Keep the plaintext out of git. Only `locked.html` is safe to publish."

Rebuilding is one command:

```bash
npm run lock -- --in private/<your-case>.html --out locked.html \
  --title 'Protected case study · Ritika Shakkerwal' \
  --heading 'This case study is password protected' \
  --standfirst '…' --hint '…'
```

**Four limits, all of them worth knowing before this page is shared.** The **ciphertext is public** — it ships in the committed file, so it can be taken offline and ground with no rate limit and no way to revoke it; password strength times KDF cost is the entire security boundary, which is why the encryptor's length gate is a hard stop rather than a warning. `crypto.subtle` needs a **secure context**, so the page decrypts over https or from localhost and nowhere else; it detects that and says so rather than crashing. Injection is `innerHTML`, so an inline `<style>` in the encrypted content **applies** and a `<script>` **does not execute**. And the page is `noindex, nofollow, noarchive, nosnippet` with `referrer: no-referrer`, and its `<title>` stays generic until unlock so nothing leaks to a crawler or a tab.

**Two deliberate non-features**, both rejected as security theater rather than overlooked: no attempt counter and no artificial delay on failure. The 600,000 PBKDF2 iterations are the real cost centre, and a counter in client-side JS is a line the attacker deletes. The one convenience that is there is a **"Keep this tab unlocked while I read" checkbox**, which stores the password in `sessionStorage` under `lockedCase.pw` and nowhere else; unticked, a reload returns the gate. A stored password that no longer decrypts is cleared silently rather than reported as the reader's mistake.

**Shell parity is an obligation here, not a nicety.** `locked.html` carries copies of the header the case shells own, and the following blocks are **byte-identical to `case.html`** and verified as such: the `.theme-switch` CSS (all four pages, MD5 `0d4a184f…`), the riri wordmark SVG markup, and the whole `.riri-logo` → `.nav-back` → `.nav-right` CSS region. It also carries the pre-paint `<head>` theme script, the theme driver IIFE and the header-hairline IIFE verbatim. **Change the shell and this is a fourth file to change** — and the change goes in `tools/locked.template.html`, then the page is regenerated. Editing `locked.html` by hand puts the two out of step and the next rebuild silently reverts you.

Its token block is **trimmed to what the page actually uses** and carries the two per-theme switch aliases (`--switch-track` / `--switch-knob`) that every page needs; the rest of the site's tokens are deliberately absent. The injected content is styled in the case-study grammar the other shells use (masthead, `.chapter-num`, `.chapter-gloss`, `.chapter-key`, centred `figcaption`, `.beat`, `.close`, and the `section:has(> .chapter-head > .chapter-num)` hairline separator at 40 above / 56 below), so encrypted copy written like a `CASES` entry renders correctly with no page edit.
